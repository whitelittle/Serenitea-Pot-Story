## 1. 运行模型

### 1.1 这段 Lua 跑在哪里
- 运行在**客户端**，由**客户端脚本**机制承载；客户端控件不受服务器节点图控制，而受客户端脚本控制（`指南` §一 L13–14）。
- 除「客户端控件容器画布中的客户端控件」与「客户端控件模板中的控件」外，其他控件均为服务器控件，服务器控件的模板索引无法被客户端脚本调用（`指南` §八 L323）。
- Lua 版本：运行时使用 **Lua 5.3**（`API` §三 L58）。
- 客户端脚本资源入口：千星沙箱 - 客户端脚本资源管理器 - 客户端脚本映射文件夹（`指南` §六 L259）。
- 脚本必须与本地文件建立**脚本映射**，且只有建立了映射的 lua 文件才会被打包上传（`指南` §七.1 L271、§七.3 L316）。
- 脚本需要与客户端控件**关联**才能生效：在客户端控件 - 脚本页签中点击添加脚本挂载（`指南` §七.3 L315）。

### 1.2 由什么触发 / 挂载对象
- 脚本宿主对象由全局变量 `script` 暴露：`script.object`（**只读**，脚本所挂载的宿主对象）（`API` §5(1) L149、§3(4) L120）。
- 客户端脚本的宿主可以是控件本身；官方指南与 `05` 都强调不要把「容器节点」当作所有脚本的唯一宿主（`05` §4 L111「不把『容器节点』当所有脚本的唯一宿主」）。
- `script.path`（只读，脚本路径）、`script.scriptMappingId`（只读，脚本映射 ID）、`script.alive`（只读）、`script.enabled`（**读写**）（`API` §5(1) L143–151）。
- 客户端控件运行时ID字段为 `id`（只读），按此查找用 `game.GetClientUIControl(controlId)`（`API` §13(1) L614、§6(1) L175）。
- 控件模板索引用 `ClientUIBaseControl.prefabIndex`（只读）；不存在通用的按 `prefabIndex` 获取现有实例接口（`01` §4 表 L76、L83）。
- 运行前提：**仅当客户端控件所处的客户端控件容器状态处于激活且可见时**，客户端控件和脚本才正常生效（`指南` §三 L34）。容器控件隐藏或关闭都会导致其中的客户端控件无法正常显示（`指南` §三.3 L58）。

### 1.3 生命周期回调
运行时按固定名称查找并调用（`API` §1 L70–82）：

| 回调 | 参数 | 功能 |
|---|---|---|
| `OnInit()` | 无 | 脚本初始化时调用 |
| `OnStart()` | 无 | 脚本启动时调用 |
| `OnEnable()` | 无 | 脚本启用时调用 |
| `OnDisable()` | 无 | 脚本停用时调用 |
| `OnUpdate(dt)` | `dt: number` | 脚本逐帧更新时调用，**不受关卡时停影响** |
| `OnLevelUpdate(dt)` | `dt: number` | 关卡逐帧更新时调用，**受关卡时停影响** |
| `OnDestroy()` | 无 | 脚本销毁时调用 |

- 逐帧开关：`script:EnableUpdate(enabled: boolean)`，false 关闭、true 重新启用（`API` §2 L88、§5(2) L159）。
- 官方文档**未声明**生命周期回调之间的精确执行顺序；`AGENT` L39 明确要求「不假定文档未声明的生命周期精确顺序」。
- 脚本读取脚本内参数：`script:GetParam(paramName: string) -> any`（`API` §5(2) L157）。
- 脚本变量配置：客户端脚本资源管理器 - 右键任意客户端脚本 - 编辑脚本变量；其中「客户端控件 ID」编辑时需填客户端控件的**模板索引**，运行时脚本可通过变量拿到该模板索引对应的运行时 ID（`指南` §八.2 L348–350）。

### 1.4 脚本之间的通信
| 机制 | 精确标识 | 说明 | 来源 |
|---|---|---|---|
| 跨脚本取实例 | `ClientUIBaseControl:GetScriptByPath(scriptPath)` | 按路径获取挂载脚本 | `API` §13(4) L673 |
| 跨脚本取实例 | `ClientUIBaseControl:GetScript(scriptMappingId)` | 按脚本映射ID获取脚本 | `API` §13(4) L674 |
| 跨脚本取实例 | `ClientUIBaseControl:GetScripts()` | 获取控件上全部脚本 | `API` §13(4) L675 |
| 跨脚本调用函数 | `script:Invoke(funcName: string, ...)` | 调用当前脚本中名称为 `funcName` 的函数 | `API` §5(2) L158 |
| 客户端 → 服务器 | `game.ServerSignal(signalName)` + `ServerSignal:*` + `ServerSignal:SendSignal()` | 客户端脚本向服务器发信号 | `API` §9 L272–305；`指南` §五.1 L194 |
| 服务器 → 客户端 | `script:RegisterServerSignalHandler(signalName, callback)` / `script:UnregisterServerSignalHandler(signalName)` | 监听服务器信号；回调参数为（信号名，信号参数数组） | `API` §5(2 L160–161)；`指南` §五.1 L195 |
| 自定义变量变化 | `script:RegisterCustomVariableChangedHandler(entityType, customVariableName, callback)` / `UnregisterCustomVariableChangedHandler` | 回调**只提供实体类型和变量名称**，当前值需通过 `game.GetGlobalCustomVariableValue` 读取 | `API` §5(2) L162–163 |

- 服务器侧发信号节点名为「发送客户端脚本信号」（`指南` §五.1 L195）。
- **发送信号延迟**：联机情况下，服务器发送信号的延迟最低为 100 ms（`指南` §五.1 L196）。
- 脚本实例可能因销毁而不再存活，使用前检查 `script.alive`（`API` §13(4) L669）。

### 1.5 客户端控件与容器的联动 / 生命周期边界
- 客户端控件容器**自身是服务器控件**（`指南` §三 L32、§四.1 L68）。
- 客户端控件容器隐藏或销毁时，客户端控件**销毁**（`指南` §五.2 L201）。
- **玩家传送、断线重连时，所有客户端控件都会被销毁然后回到初始状态**；若要保留传送前界面需奇匠自行处理恢复逻辑（`指南` §五.3 L205）。
- 动态创建资格（关键限制）：仅**存为模板**的客户端控件的父节点支持通过接口动态创建；**挂载在主屏中的客户端控件，以及存为模板的客户端控件的子节点，均不支持通过脚本接口动态创建**（`指南` §八.1 L334–335；`01` §4 L94、§5 L94）。

补充事实：
- 「组合式按钮」**不是官方控件类型**，而是「容器节点 + 图片/文本框 + 光标检测区域」的实现方案称呼（`AGENT` L36；`08` L43、L62–76）。

- 预设按钮的四态槽位绑定在编辑器侧完成；Lua 只读取 `ClientUIReferenceControl.referencedPrefabIndex` 做诊断，**不能赋值**（`08` L89；`API` §25 L935）。
- 界面控件资产中还有**客户端控件容器**，它属于服务器控件资产，不是客户端控件类型（`指南` §四.1 L68、§三 L32）。
- `TextBoxControl` / `TextWindowControl` / `ImageControl` / `UIAnimationControl` / `FullscreenUIAnimationControl` / `PresetButton` / `UIKeyHintControl` / `CursorEventArea` / `GridScrollerControl` / `ReferenceControl` / `ContainerControl` 是 `指南` 中给出的**API 文档检索关键字**，不是 Lua 类型名本身（`指南` §四.2 L86–188；`08` L25–37 明确「查 API 时使用对应的英文类型名」）。

- `CursorEventData:GetUIPos()` → 以画布左下角为原点获取当前屏幕 UI 坐标，坐标比例和布局坐标一致（`API` §19(2) L837）。

- `CursorEventData:GetUIPosDelta()` → 本次事件的屏幕 UI 位移（§19(2) L839）。
- 父子层级中的位移、缩放、可见性、Alpha、镜像与裁剪效果由运行时 UI 层级共同决定；使用组合布局时应验证实际显示结果（`API` §13(3) L648）。
- 文档**未**给出画布分辨率、坐标单位、跨父级坐标换算公式 → `UNKNOWN`（`AGENT` L43 要求「不猜分辨率或跨父级变换」）。
- 「Alpha」「镜像」「裁剪」在文档中**只在上句出现名称，没有对应的独立 API 名称**（图片透明度以 `imageColor` 的 ColorValue 承载，颜色通道为 0–255；见 `API` §4(1) L129、`01` §5 L95）。

### 3.7 计时器与逐帧
- **没有名为 Timer / Delay / setTimeout / Schedule 的 API**：在 `API` 全文与 `索引` 全表中均未出现。
- 逐帧驱动由生命周期提供：`OnUpdate(dt)`、`OnLevelUpdate(dt)`（`API` §1 L80–81）；开关 `script:EnableUpdate(enabled)`（§2 L88）。
- 基于时间的间隔与延迟回调能力由 `TweenSequence:AppendInterval` / `TweenSequence:InsertCallback` / `TweenSequence:AppendCallback` 提供（`API` §8(2) L257、L261、L258）。
- 帧率、`dt` 精度、每帧调用上限：文档**未明确** → `UNKNOWN`。
- `AGENT` L38 规定「纯 Tween 不为了计时开启逐帧」；`05` §4 L112 提示「隐藏、未激活和脚本停止是不同现象」。

## 5. 硬限制与配额

### 5.1 明确列出的禁用项（`API` §三 L58–66）
运行时使用 Lua 5.3。以下标准库能力**不可用**：
- `string.dump`
- `io.*`（全部）
- `coroutine.*`（全部）
- `os.*` —— 除 `os.time`、`os.date`、`os.clock`、`os.difftime` 外
- `debug.*` —— 除 `debug.traceback` 外

标准库补充的方法（文档明确新增）：`math.isnan(n)`、`math.isinf(n)`。
`AGENT` L34 复述：「不使用 `io.*`、`coroutine.*`、`string.dump`，`os` 和 `debug` 只用 API 文档允许的成员」，并要求「优先 `local`，避免无界循环和未声明的宿主全局」。

## 6. 对「星露谷类」的可行性判断

前置事实（全部来自上文提取）：客户端脚本运行在 Lua 5.3 且 `io.*`/`coroutine.*`/`string.dump` 被禁；Lua 侧**没有**世界、实体、元件、瓦片地图、物理、碰撞、寻路、存档、随机数（未提）、自定义变量写入；平台提供的可编程对象只有 `ClientUIBaseControl` 家族的 11 种客户端控件 + `Color`/`Script`/`Tween`/`TweenSequence`/`ServerSignal`/`CursorEventData`/`EnumItem`；唯一的逐帧入口是 `OnUpdate(dt)` / `OnLevelUpdate(dt)`；唯一的屏幕单位是 UI 坐标（`GetAnchoredPosition`/`SetAnchoredPosition`/`GetSizeDelta`/`anchoredPositionX,Y`）。

### 6.1 能做
1. **屏幕空间 2D 表现层**：用 `ClientUIImageControl` 承载所有可见图元（地形块、角色、道具、作物），用 `anchoredPositionX/Y` 或 `SetAnchoredPosition(x,y)` 逐帧改位置，用 `SetSizeDelta` 改大小，用 `SetLocalScale`/`SetLocalRotation` 做缩放旋转，用 `SetSiblingIndex`/`SetAsFirstSibling`/`SetAsLastSibling` 控制前后遮挡（文档口径：数值越大通常显示越靠上，`API` §13(2) L642）。图片来源只走 `SetImage(imageSource, imageId)`，`Enum.ImageSource` 提供 8 种来源分类（§11(17)）。
2. **逐帧游戏循环**：`OnUpdate(dt)` 即每帧回调，且不受关卡时停影响（§1 L80）；需要暂停世界但保留 UI 逻辑时可切到 `OnLevelUpdate(dt)` 并用 `game.PauseLevelTime(true)`（§1 L81、§6(4) L206）。可用 `script:EnableUpdate(false)` 关掉不需要的逐帧（§2 L88）。
3. **键盘/鼠标操控**：移动用 `Enum.KeyboardKeyCode.MoveForwardKey`(W)/`MoveBackwardKey`(S)/`MoveLeftKey`(A)/`MoveRightKey`(D)/`InteractKey`(F)/`NormalAttackKey`(鼠标左键)/`SprintKey`(鼠标右键) 等语义键，或 43 个 `CraftspersonKeyN`；监听用 `AddKeyEventListener(eventType, callback)`，事件枚举为 `...Down`/`...Up` 对（§26(3) L1033–1200）；交互/点击/拖拽用 `AddCursorEventListener` + `Enum.CursorEventType` 8 值；鼠标位置用 `game.GetCursorUIPos()` 或 `CursorEventData:GetUIPos()`。
4. **背包/商店/作物栏等网格 UI**：`ClientUIGridScrollerControl` + `itemPrefabIndex` + `RefreshItems(itemCount, callback)` + `GetItemIndex` + `ScrollToItemAt`，这是文档声明的**复用列表**机制（§20）。
5. **动效与过渡**：位置/大小/锚点/中心/缩放/旋转/颜色/字号/字色/背景色/描边色/羽化宽度/羽化范围/`fillAmount`/`scrollProgress` 都被标注为 Tweenable，配 `Enum.EaseType` 31 种缓动、`Tween:SetLoops`（负数无限）、`TweenSequence` 的 Append/Join/Insert/AppendInterval/AppendCallback 可编排时序（§7、§8、§11(1)）。
6. **文本与本地化 UI**：`ClientUITextBoxControl` 与 `ClientUITextWindowControl` 完整支撑 HUD 与对话（§15、§16）；本地化用 `game.GetText(textMapId)`（§6(4) L214）。
7. **音效反馈**：`game.PlayAudio2D(audioId)` / `StopAudio` / `IsAudioAlive`，以及预设按钮 `clickAudioId`、动效 `playSoundEffect`（§6(4)、§17、§22、§23）。
8. **与服务器的回合式通信**：所有「存档」「掉落」「结算」类需求只能通过 `game.ServerSignal(name)` 发信号给服务器节点图，用 `script:RegisterServerSignalHandler(name, callback)` 收回执（§5(2)、§9）。联机下这条路径最低 100 ms 延迟（`指南` §五.1 L196）。

### 6.2 不能做 / 必须打回服务器或另想办法
1. **碰撞检测**：文档里没有任何碰撞 API。做不了「碰撞」这件事，只能由 Lua 用已提取的坐标字段自行做数值比较（此为实现推论，**非文档声明**）。
2. **物理**：没有任何物理 API。
3. **寻路**：没有任何寻路/NavMesh API。
4. **瓦片地图**：没有瓦片地图控件、没有瓦片数据、没有地图 API。所谓「地图」只能是若干 `ClientUIImageControl` 的排列（此为结构推论）。
5. **持久化存档**：文档中完全没有存档/读档/序列化 API。自定义变量也只有 `game.GetGlobalCustomVariableValue` 一个读接口（§6(3) L200）和 `RegisterCustomVariableChangedHandler` 监听（§5(2) L162），**客户端没有写接口**。
6. **世界/实体交互**：`01` §4 L85 明确「Lua 侧没有直接与实体元件交互的能力」。实体/元件只在服务器信号参数位出现（`AddEntity`/`AddPrefabId`/`AddGuid`/`AddConfigId` 系列）。
7. **音乐/BGM**：只有「2D 音效」播放，没有任何音乐/背景音乐/音量/循环音乐 API。
8. **随机数**：`math.random` 未在文档出现 → 不可依赖。`math.isnan`/`math.isinf` 是文档唯一明确补充的 math 成员。
9. **协程**：`coroutine.*` 被明确禁用，任务调度只能靠 `OnUpdate` 累加或 `TweenSequence`。
10. **多文件模块 `require`**：`01` §1 L12 明确「当前包内 API 文档和官方使用指南**没有**给出 Lua `require` 的模块路径语法」；跨脚本能力只有 `GetScriptByPath`/`GetScript`/`GetScripts`/`script:Invoke`。
11. **「持续按住」语义**：`Enum.KeyEventType` 只有 Down/Up 两态，没有 Held/Repeat 事件。
12. **传送/断线后界面保持**：所有客户端控件会被销毁并回到初始状态，需自行实现恢复逻辑（`指南` §五.3 L205）。

### 6.3 唯一可行的渲染与驱动路径
从上述事实出发，**唯一被文档声明的、可编程的屏幕渲染与逐帧驱动路径是：**
> **用「客户端控件」当图元，用 `OnUpdate(dt)` 当主循环，用 `anchoredPositionX/Y`（或 `SetAnchoredPosition`）当世界坐标，用 `SetSiblingIndex` 当图层顺序。**

具体拆开：
- **渲染载体**：只能是 `ClientUIImageControl`（精灵/瓦片）、`ClientUITextBoxControl`/`ClientUITextWindowControl`（文本）、`ClientUICursorEventAreaControl`（不可见命中区）、`ClientUIPresetButtonControl`（四态按钮）、`ClientUIGridScrollerControl`（列表）。没有任何非 UI 的渲染对象。
- **世界坐标**：只能是 UI 坐标。根级控件用「以画布左下为原点」的 `anchoredPositionX/Y`；有父级时是「与父层级中心的相对偏移」（`API` §13(3) L652–653）。因此「摄像机」只能由 Lua 移动一个父容器节点 + 子控件反向偏移来实现（结构推论）。
- **主循环**：只能是 `OnUpdate(dt)`（不受关卡时停）或 `OnLevelUpdate(dt)`（受关卡时停）。**没有 Timer**，所有周期性行为要么靠 `OnUpdate` 累加 `dt`，要么靠 `TweenSequence:AppendInterval` + `AppendCallback`/`InsertCallback`。
- **对象池**：控件级用 `game.InstantiateClientUIControl` / `game.DestroyClientUIControl`（仅对存为模板的父节点可用）；列表级用 `itemPrefabIndex` + `RefreshItems` 让引擎复用列表项（网格项**不得**用 `InstantiateClientUIControl`，`16` §1 L26）。
- **碰撞/可玩性判定**：全部只能写成 Lua 内部的坐标数值比较，平台不提供任何支持。
- **必须离开客户端才能完成的部分**：存档、掉落、结算、实体状态变更，全部只能通过 `game.ServerSignal(...) + SendSignal()` 交给服务器节点图，客户端只能通过 `RegisterServerSignalHandler` 和 `GetGlobalCustomVariableValue` 读回结果。

**结论（上述事实的直接后果）**：在文档声明的能力范围内，「星露谷类」只能被实现为一个**基于 UI 控件、由 `OnUpdate(dt)` 驱动的屏幕空间 2D 图元集合**——即用一个运行时画布上的若干 `ClientUIImageControl` 模拟地块与角色、用 Lua 逐帧改 `anchoredPositionX/Y` 实现移动、用 Lua 自己的数值比较实现判定、用 `ServerSignal` 把一切需要持久化的东西交给服务器。文档**未声明**任何超出这条路径的渲染、物理、寻路、存档或世界对象能力。
