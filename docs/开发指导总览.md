## 1. 任务书

### 1.1 目标

用**千星奇域「客户端脚本 + 客户端控件」**这套能力，做一个**系统完整的星露谷类农场生活模拟**：

> 俯视 2D、像素风、可种田、可养殖、可采矿战斗、可钓鱼、可与 NPC 交往、有季节与节日、有经济与制作、能长期玩下去。

- **不要**做"蒙德首发"式的区域切片，要做**完整系统骨架 + 可玩内容量**；
- **可以**（也应该）借用附录 C/D 里的系统分类、节奏母表、验收标准；
- 但**平台能力优先于设计文档**：设计文档里任何平台做不到的东西（物理、寻路、存档、世界实体），按 §2 的路径改造或降级，不许硬写。

### 1.2 三条硬指标的验收定义

| 指标 | 空洞说法 | 本项目的可判定定义 |
|---|---|---|
| **系统完善** | "功能很多" | §4 的 28 个系统全部有**数据结构 + 状态机 + 存档字段 + UI 入口**；其中 12 个核心系统达到"完整"档（见 §4 表格的"目标档"列）。任意两个核心系统之间至少有一条**双向联系**（产出→消耗 或 解锁→回报），不存在"进去玩一下就拿奖励走人"的孤岛系统 |
| **美术优秀** | "好看" | 全部可见图元满足 §5 的像素与色板规范；**没有任何控件使用未经验证的 imageId**；同一屏幕上不出现两种互斥画风；所有状态变化都有视觉反馈（至少 1 帧变化或 1 次 Tween）；关键动作（走路/挥工具/收获/受击）有逐帧或多帧表现，不是瞬移式硬切 |
| **可玩性高** | "有意思" | 新玩家在**不看任何说明**的情况下，3 分钟内能完成"出门→锄地→播种→浇水→睡觉→第二天看到作物长了一格"这条闭环；每天有 ≥3 条可选的推进路线；前 3 天有明确的短期目标，第 1 季有中期目标，第 1 年有长期目标（对应附录 C 的一年四季母表） |

### 1.3 非目标（明确不做，省下次数）

- 不追求真机与编辑器 1:1 的表现一致性（先把模拟/静态层面做对）。
- 不做联网对战、多人同步玩法（信号只用于**存档与权威结算**）。
- 不实现平台未声明的能力：碰撞体、物理、寻路、瓦片地图对象、世界实体、音频总线。
- 不做任何需要 `io.*`、`coroutine.*`、`require` 之外模块加载的架构。
- 不为了"看起来大"而堆没有闭环的系统。

### 1.4 交付物清单

每次批次只产出下面这些类型，不要产出别的：

```
<repo>/
├─ src/                  Lua 源码（唯一会被编辑器挂载的入口 + 拆分模块）
├─ data/                 数据表（作物/物品/NPC/事件/地图），Lua 表或 JSON
├─ maps/                 地图数据（JSON/数组文本）
├─ art/                  美术规范、色板、素材清单、图集（如允许自定义素材）
├─ tools/                纯 Python/Node 脚本，产出文本，不依赖编辑器
├─ docs/                 设计、规格、决策记录、UNKNOWN 与探针
└─ tests/                静态校验脚本 + 期望输出
```

## 2. 平台事实基线（**先读，否则一切设计都是空中楼阁**）

> 详细版与出处见 [`平台能力清单.md`](平台能力清单.md)。这一节只放结论。

### 2.1 这个平台是什么

千星奇域的客户端脚本运行在 **Lua 5.3** 上，可编程对象**只有 UI 控件体系**：

`ClientUIBaseControl`（基类）、图片、文本框、文本视窗、预设按钮、光标检测区域、网格视窗、按键提示、界面动效、全屏界面动效、容器节点、模板引用控件，加上 `Color / Script / Tween / TweenSequence / ServerSignal / CursorEventData / EnumItem`。

生命周期回调固定为 `OnInit / OnStart / OnEnable / OnDisable / OnUpdate(dt) / OnLevelUpdate(dt) / OnDestroy`。

### 2.2 能做 / 不能做

| 需要的能力 | 结论 | 替代路径 |
|---|---|---|
| 屏幕坐标的图片图元 | **有**（`ClientUIImageControl` + `anchoredPositionX/Y` 可 Tween） | 地形、角色、道具、作物全部用它 |
| 逐帧主循环 | **有**（`OnUpdate(dt)`，不受关卡时停；`OnLevelUpdate(dt)` 受时停） | 游戏主循环 |
| 键盘输入（按下/抬起） | **有**（`AddKeyEventListener` + `Enum.KeyEventType`） | 移动、工具、菜单 |
| 鼠标/触屏（含拖拽） | **有**（`AddCursorEventListener` + `Enum.CursorEventType` 8 值） | 点击、拖拽、放置 |
| 手柄 | **有**（导航事件 + 摇杆轴） | 次要输入 |
| 列表/背包 | **有**（网格视窗 `itemPrefabIndex` + `RefreshItems`） | 背包、商店、图鉴 |
| 动画 | **Tween / TweenSequence**（31 种缓动、可循环、可序列） | 位移、缩放、淡入淡出、转场 |
| 音效 | **有**（`game.PlayAudio2D` / `StopAudio`） | 反馈音 |
| 文本与本地化 | **有** | HUD、对话 |
| **碰撞检测** | **没有** | Lua 自己做数值判定（网格占用表 + AABB 近似） |
| **物理** | **没有** | 同上，不要设计需要物理的玩法 |
| **寻路** | **没有** | 网格 BFS（自己写，注意每帧预算） |
| **瓦片地图对象** | **没有** | "瓦片"= 一批图片控件；见 §3.4 |
| **存档 / 读档** | **客户端没有** | 走服务器信号；见 §3.9 |
| **写自定义变量** | **客户端没有（只能读 + 监听变化）** | 同上 |
| **世界 / 实体 / 元件交互** | **没有** | 实体只作为信号参数出现 |
| **音乐 / BGM / 音量** | **文档未声明** | 只用 2D 音效；`UNKNOWN` |
| **`math.random` / `table.*`** | **文档未逐条声明** | `UNKNOWN`：不得依赖，先写探针；随机数可用自实现的 LCG |
| **协程 `coroutine.*`** | **明确禁用** | 用 `OnUpdate` 累加 `dt` 或 `TweenSequence` 排期 |
| **`require` 模块寻址** | **文档未给出路径语法** | 拆模块前先做探针；未确认前**交付单文件版本** |

### 2.3 唯一可行的渲染与驱动路径

> **用「客户端控件」当图元，用 `OnUpdate(dt)` 当主循环，用 `anchoredPositionX/Y` 当世界坐标，用 `SetSiblingIndex` 当图层顺序。**

没有第二条路。任何设计如果不能落成"一批控件的属性被逐帧改写"，就是不可实现的。

### 2.4 硬限制（会直接影响架构，必须记住）

1. **动态创建资格受限**：只有**存为模板**的客户端控件的父节点能 `game.InstantiateClientUIControl`；主屏画布里的控件、模板内的子节点都不行。
2. **网格列表项不能用 `InstantiateClientUIControl` 创建**：只能写 `itemPrefabIndex` 然后 `RefreshItems`。
3. **容器隐藏/销毁 → 其中控件销毁**；**玩家传送、断线重连 → 所有客户端控件销毁并回到初始状态**，恢复逻辑要自己写。
4. **光标事件前提**：容器 `showCursor = true`，目标 `raycastTarget = true`。
5. **没有 Timer API**：间隔与延迟只能用 `OnUpdate` 累加 `dt`，或 `TweenSequence:AppendInterval / AppendCallback / InsertCallback`。
6. **`printerr` 不抛异常、不中断**：故障分支必须显式 `return` 或改状态。
7. **`pcall` 的第一个返回值只说"有没有抛错"**：`fn` 返回 `false, reason` 时要接成 `ok, value, reason` 分别判断。
8. **七种编号不能混用**：容器节点索引、`prefabIndex`、运行时 `id`、`imageId`、`scriptMappingId`、`itemPrefabIndex`、`referencedPrefabIndex`。
9. **颜色通道是 0–255**，不是 0–1。
10. **联机信号延迟最低 100 ms**：不要让玩法手感依赖信号往返。

### 2.5 `UNKNOWN` 清单与探针协议

以下事实文档没写死，**必须写成探针，不许当已知**：帧率与 `dt` 精度、每帧预算、画布分辨率、控件数量上限、列表容量上限、`math.random`/`table.*` 可用性、`require` 路径语法、存档序列化方式、音乐播放、Alpha/镜像/裁剪的接口名、生命周期回调的精确顺序、`StopAnimation` 的收尾帧。

**探针协议**（照抄附录 B 的做法）：
- 一次只验一件事；只用文档已声明的接口；带唯一前缀与开关；能一键关掉；定位完删掉或移入 `tools/probes/` 存档。
- 探针产出写进 `docs/探针记录.md`，格式：`问题 → 探针代码位置 → 观察结果 → 结论 → 是否影响架构`。
- 结论未出之前，依赖它的那**一小段**代码冻结，其余照常推进。

## 3. 总体架构

### 3.1 分层

```
┌─────────────────────────────────────────────┐
│ UI 层       HUD / 背包 / 商店 / 对话 / 菜单    │  控件 + RefreshItems + Tween
├─────────────────────────────────────────────┤
│ 表现层      WorldView（控件池、帧动画、相机）   │  只读模型，写控件属性
├─────────────────────────────────────────────┤
│ 模拟层      World（tick(dt)：时间、作物、NPC、刷怪）│  纯 Lua 数据，不碰控件
├─────────────────────────────────────────────┤
│ 数据层      data/*（作物表、物品表、地图表、事件表）│  纯表，可被工具生成
├─────────────────────────────────────────────┤
│ 输入层      InputMap（按键/光标 → 意图 Intent）  │  只发意图，不改状态
├─────────────────────────────────────────────┤
│ 存档层      SaveBridge（信号上行 + 变量读回）    │  唯一出口
└─────────────────────────────────────────────┘
```

**铁律：模拟层不许出现任何控件引用；表现层不许改游戏状态。** 这条守住了，后面换素材、改渲染、加系统都不会互相踩。

### 3.2 目录结构（工程文件树）

```
<game>/
├─ src/
│  ├─ main.lua              唯一挂载入口：只注册生命周期、驱动 tick 与渲染
│  ├─ core/
│  │  ├─ state.lua          五态机（初始化/启动/运行/失败/销毁）
│  │  ├─ clock.lua          游戏时间：分/时/日/季/年、时停
│  │  ├─ events.lua         事件总线（订阅/发布，替代信号做本地广播）
│  │  ├─ pool.lua           控件对象池（有界、可回收）
│  │  └─ rng.lua            自实现随机数（不依赖 math.random）
│  ├─ world/
│  │  ├─ map.lua            网格地图数据 + 占用/通行判定
│  │  ├─ player.lua         玩家状态与移动
│  │  ├─ farming.lua        耕地/播种/浇水/生长/收获
│  │  ├─ npc.lua            NPC 日程与关系
│  │  ├─ combat.lua         简战斗与敌人
│  │  └─ save.lua           存档字段聚合/应用
│  ├─ view/
│  │  ├─ camera.lua         相机偏移 → 控件位置
│  │  ├─ tiles.lua          地形控件层
│  │  ├─ sprites.lua        角色/作物/NPC 控件层
│  │  ├─ effects.lua        特效层
│  │  └─ anim.lua           帧动画播放器
│  ├─ ui/
│  │  ├─ hud.lua            时间/金钱/体力条
│  │  ├─ inventory.lua      背包网格
│  │  ├─ shop.lua / dialog.lua / menu.lua / journal.lua
│  └─ input/inputmap.lua
├─ data/*.lua               作物/物品/NPC/事件/配方/地图
├─ maps/*.json
├─ art/                     色板、素材清单、图集
├─ tools/                   生成器与校验器（Python/Node）
├─ docs/                    规格、决策、探针记录
└─ tests/                   静态校验与期望输出
```

> 拆模块前先做 `require` 探针（§2.5）。未确认时把 `src/` 视为"逻辑分区"，交付**单文件合并版**，并在文件头用注释标出分区边界。

### 3.3 主循环与时间预算

```lua
function OnUpdate(dt)
    if state ~= "RUNNING" then return end
    dt = finiteDt(dt)            -- 类型/NaN/Inf/<=0 全部拦掉，见附录 B
    clock:advance(dt)            -- 游戏时间推进（非暂停时）
    world:tick(dt)               -- 模拟：作物、NPC、敌人、刷新
    view:sync(world)             -- 表现：只读模型，改写控件
    ui:drain()                   -- 处理本帧产生的 UI 事件
end
```

- **分帧预算**：把重活（寻路、地图刷新、存档序列化）拆到独立 tick 计数器上，例如每 N 帧做一次；绝不在 `OnUpdate` 里建 Tween、遍历整棵控件树、重新注册监听。
- **不需要逐帧就关掉**：`script:EnableUpdate(false)`。空闲时保持关闭，只有移动/动画/计时需要时才开——这是这个平台最重要的性能纪律。
- **重复间隔逻辑保留余数**（`while elapsed >= interval do elapsed = elapsed - interval end`），并设补执行上限，禁止无界 `while`。

### 3.4 世界模型：瓦片即控件

- 地图 = 二维网格数据（`maps/*.json`），**数据层不知道控件存在**。
- 视野内每个格子对应一个地形图片控件；控件从**池**里借，滚动时重新赋值 `SetImage` 与位置，不是"一格一控件常驻"。
- **相机**：移动一个父容器节点，子控件相对偏移；不要逐帧改全屏每个控件的世界坐标。
- **图层顺序**：地面层 / 装饰层 / 实体层 / 特效层 / UI 层，用 `SetSiblingIndex` 或分层容器固定。
- **碰撞**：网格通行表 + 实体占位表，Lua 数值判定；不做像素级碰撞。
- 坐标一律走 UI 坐标（无父级时以画布左下为原点；有父级时是与父级中心的相对偏移）。**布局坐标与光标坐标不是一回事**，跨层换算前必须确认父链缩放=(1,1,1)、旋转=(0,0,0)。

### 3.5 实体与对象池

- 所有会反复出现/消失的东西（作物、掉落物、NPC、敌人、特效、飘字）都走对象池：`game.InstantiateClientUIControl` 创建（**父节点必须是模板**），`game.DestroyClientUIControl` 释放。
- **借出前必须 reset 全部被改过的属性**（位置、缩放、旋转、颜色 alpha、可见性、active）——否则残留上次状态。
- 池**有界**：满了就跳过新特效，不扩容、不打断已有效果。
- 池容量按**实际存活实例**计算，销毁/失效的引用要剔除。

### 3.6 数据驱动

- 所有数值进 `data/`，代码里不出现魔法数字。
- 数据表结构（示例，字段以附录 C 的图鉴数据规范为准）：

```lua
-- data/crops.lua
return {
    { id = "turnip", name = "芜菁", season = {"spring"},
      stages = {1, 1, 1, 1}, daysPerStage = 1, regrow = false,
      seedPrice = 20, sellPrice = 35, sprite = {stageBase = 100100} },
}
```

- 表格由 `tools/` 的生成器从 CSV/JSON 产出 Lua，避免手写错漏。

### 3.7 输入

- 输入层只产出**意图**：`{move={x,y}, useTool=true, interact=true, openMenu="inventory"}`。
- 持续动作用 Down 置位、Up 清位，真正位移放 `OnUpdate` 乘 `dt`（平台没有"持续按住"事件）。
- 失焦/停用必须清方向位 + 注销监听；**只注销自己注册的**，不要调 `RemoveAll*`。
- 键盘语义键优先（`MoveForwardKey/InteractKey/NormalAttackKey/...`），功能键用 `CraftspersonKey1..43`；手柄走导航事件 + 摇杆轴。

### 3.8 状态机与事件总线

- 全局：`NEW → STARTING → RUNNING → FAILED / DESTROYED`（照附录 B 模式 1）。
- 每个系统自带小状态机（如作物：`SEED → SPROUT → GROW → READY → HARVESTED / WITHERED`）。
- 本地事件总线（订阅/发布）用于跨系统解耦；**跨端**才用 `game.ServerSignal`。

### 3.9 存档与服务器协作（**架构级约束**）

客户端**没有存档 API、没有写自定义变量的 API**。所以：

- 存档 = `SaveBridge`：把 `world:serialize()` 的结果通过 `game.ServerSignal("SaveGame")` 上行，由服务器节点图落库；
- 读档 = 服务器下发信号 → `script:RegisterServerSignalHandler` 接住 → `world:deserialize()`；
- 变量监听只用来读回权威值（`game.GetGlobalCustomVariableValue`）。
- **传送/断线重连会销毁全部客户端控件**：重连后必须重新拉权威数据并重建界面，不能假设"界面还在"。
- 信号延迟最低 100 ms：**不要让手感依赖它**（本地先表现，服务器只做权威结算）。

## 5. 美术管线（"美术优秀"怎么落地）

### 5.1 像素规范（先定死，再画）

| 项 | 规定 |
|---|---|
| 基准瓦片 | 32×32（画布 16:9；所有尺寸按它取整） |
| 角色 | 32×48（含头顶余量），四向 × 4 帧行走 |
| 色板 | 主色 ≤ 32 色，含 4 档明度阶梯；季节只换"环境色板"不换角色色板 |
| 描边 | 外描边 1px，深色同色系（不用纯黑） |
| 光 | 左上光源；投影 1 格，透明度固定 |
| 禁止 | 抗锯齿、半像素缩放、混用写实与像素 |

### 5.2 素材来源与 **imageId 铁律**

- 平台图片走 `game.SetImage(imageSource, imageId)`，`imageId` **必须来自真实资产清单**。
- 可用的查询渠道：
  1. `assets/V7.1图标合集/`（仓库内 25 张图鉴，按 100 个 ID 一块排列，`?` 表示未收录）；
  2. 工具箱 <https://tool.xiaomol444.xyz/>（按 ID 浏览内置资产）；
  3. 用户自己的编辑器资产清单。
- **绝对禁止编造 imageId。** 用不到就先用**几何图元 + `imageColor` 染色**做占位（`100001` 方块 / `100002` 圆 / `100003` 三角 / `100004`、`100005` 星形 / `100006` 圆环，见 `图标合集100000.jpg`），占位块必须在上线前替换。
- `Enum.ImageSource` 有 8 种来源（`StaticReference / Item / Equipment / Skill / UnitStatus / Faction / Currency / Prefab`），取图前先确认该 `imageId` 属于哪种来源。

### 5.3 需要生产的素材清单（按系统列全）

地形（草地/泥土/耕地/湿土/路面/水/崖）、建筑（房屋/畜舍/商店/工作台）、角色（玩家四向行走、工具挥动、受伤）、NPC（每人四向 + 立绘）、作物（每种 ≥4 阶段 + 收获物）、树木（3 阶段 + 树桩）、动物（鸡/牛/羊各 ≥2 帧）、矿石与矿洞、鱼类图标、道具图标（工具/种子/食物/矿物）、UI（面板九宫、按钮四态、图标、体力/时间条）、特效（尘土/水花/打击/星光）、天气（雨/雪）。

### 5.4 三段式：**占位 → 拟合 → 精修**

1. **占位**：几何图元 + 颜色编码，先把逻辑与手感跑通。**这一阶段不许停下来等美术。**
2. **拟合**：用已验证的内置 `imageId` 替换占位，调整尺寸/锚点/层级，做到"看起来是个游戏"。
3. **精修**：补帧动画、补特效、统一色板，做一次全屏走查（见 5.5）。

### 5.5 质量检查清单

- [ ] 所有可见控件都用了**已验证**的 imageId（有出处记录）
- [ ] 像素对齐：位置与尺寸都是 32 的整数倍或半格
- [ ] 同一屏没有混用两种风格/两套色板
- [ ] 图层顺序正确（地面 < 装饰 < 实体 < 特效 < UI）
- [ ] 每个状态变化都有视觉反馈
- [ ] 相机移动不抖动（取整后再赋值）
- [ ] 缩放/旋转不产生模糊（除非刻意）
- [ ] `?` 占位图元在上线前全部替换

## 7. 工作流协议（省次数，最重要的一节）

### 7.1 一次回复 = 一个批次

一个批次 = 一个可独立验收的产出（一个系统的一个切片 / 一个工具 / 一份规格）。**不要在一次回复里同时开三个系统。**

### 7.2 批次固定流程（照做，不要自由发挥）

```
1. 复述本批次目标（1 行）
2. 列出要读的文件（只读必要的，别整仓扫描）
3. 写代码 / 写数据 / 写文档
4. 静态自检：附录 B 的「交付前反查清单」逐条过
5. 提交到 git（§7.4）
6. 按 §7.5 的格式回报
```

### 7.3 禁止行为

- ❌ 编造 API 名、控件名、枚举值、imageId、动效 ID
- ❌ 用其它引擎（Unity/uGUI/Godot）的经验补平台没声明的行为
- ❌ 一次回复塞多个不相关系统
- ❌ 留 `TODO` / 半成品 / "这里以后再补"（要么做完，要么明确写进 `docs/待办.md` 并说明为什么）
- ❌ 把 `UNKNOWN` 写成"应该可以"
- ❌ 提交二进制大文件、密钥、`node_modules`
- ❌ 声称"已实测/真机通过"，除非真有运行证据

### 7.4 提交规范

- 分支：`feat/<系统>`、`fix/<问题>`、`docs/<主题>`、`tools/<工具名>`
- 提交信息（中文，一行主题 + 正文要点）：

```
feat(farming): 耕地与播种闭环

- data/crops.lua：春季 6 种作物
- src/world/farming.lua：耕地→播种→浇水状态机
- src/view/tiles.lua：耕地/湿土贴图切换
验收：锄地→播种→浇水→过夜，作物进入 SPROUT
```

- 每个批次**必须**推送到 GitHub（仓库：<https://github.com/whitelittle/Serenitea-Pot-Story>）。
  推送凭据：如果 `git push` 因凭据助手失败，用一次性 token URL（见 §7.6）。
- 不覆盖别人已提交的内容；冲突时以"更新的规格文档"为准，并在 `docs/决策记录.md` 留一条。

### 7.5 回报格式（每次回复结尾照抄）


## 10. 术语与约定速查

| 术语 | 含义 |
|---|---|
| 控件 | 客户端控件（图片/文本框/网格/容器…），本项目唯一的"图元" |
| 模板 | 存为模板的控件，**只有它的父节点能动态创建实例** |
| `prefabIndex` | 控件模板索引（只读，身份） |
| `id` | 运行时控件 ID（只读，实例身份） |
| `imageId` | 图片资产 ID（只读字段，用 `SetImage` 设） |
| 意图 Intent | 输入层产出的动作描述，不含状态 |
| 池 Pool | 有界控件对象池，借出前必须 reset |
| 批次 | 一次 AI 回复产出的一个可验收单元 |

---

**最后一条，也是最重要的一条**：这个平台的本质是"**用 UI 控件拼一个游戏**"。任何设计如果不能落成"一批控件的属性被逐帧改写"，就先改设计，而不是先写代码。
