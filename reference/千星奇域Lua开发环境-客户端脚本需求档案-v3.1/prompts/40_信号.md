# 信号、变量与跨脚本

先查 API §5、§6、§9、§11 和 §13(4)。本地动画不需要服务器信号。

## 服务器通信

上行：`game.ServerSignal(name)` → 按协议顺序 `Add...` → `SendSignal()`。名称、参数类型与顺序必须来自双方约定；“第一个参数一定是实体”不是 API 要求。

下行：`script:RegisterServerSignalHandler(name, callback)`，回调参数是信号名、参数数组；解除用 `UnregisterServerSignalHandler(name)`。成功注册一条就记录其清理，不能等整批成功才登记。

自定义变量监听回调只给实体类型和变量名；使用 `game.GetGlobalCustomVariableValue(entityType, name)` 读取当前值，再刷新界面。监听与注销成对，不无限重复注册。

数据到达与演出播放解耦：先更新本地视图目标，再触发表现。中断动画不改变服务器权威结算。

## 客户端跨脚本

通过控件 `GetScriptByPath(path)`、`GetScript(scriptMappingId)` 或 `GetScripts()` 取得脚本；没有 `game.GetScript`，也不要把路径传给按映射 ID 查找的方法。

检查返回脚本 `alive` 后，通过该实例 `:Invoke(funcName, ...)` 调其全局函数。`Invoke` 无返回值，不把子脚本当同步查询函数。传参只采用运行时明确支持的类型，不靠样本猜所有 Lua 对象都能传。

普通 Lua 模块函数调用与挂载脚本实例 `Invoke` 是两回事。前者模块寻址前提见 [文件树](10_文件树.md)。

官方指南说明传送/重连会重建客户端控件，需重新读权威数据并恢复界面；它不是“动画完成了就一定落库”的机制。不要把每段 Tween 都变成网络往返。
