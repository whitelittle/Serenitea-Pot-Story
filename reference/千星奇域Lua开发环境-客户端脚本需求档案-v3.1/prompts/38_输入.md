# 输入与导航

查 API §13(5–7)、§17–§19、§24、§26，先确认控件类型。基类有按键监听，但光标监听在预设按钮和光标检测区域，不能因为“都是控件”就对容器调用专用方法。

按结构区分“组合式按钮”与“预设按钮控件”，不使用“动态/静态”作为类型对照。自定义交互优先选择组合式：`ClientUIContainerControl` + 显示内容子控件 + `ClientUICursorEventAreaControl`；容器组织内容，光标检测区域负责命中和事件，Lua 管理自定义状态。需要编辑器管理四态、按键样式或点击音效时选择 `ClientUIPresetButtonControl`。换图、改字或 Tween 不专属于组合式按钮，已有预设按钮先核对对应显示子控件和基类 API；详见 [防混淆清单](../docs/08_控件名称与CONFIG配置.md#按钮术语与防混淆清单)。

采用本包的四态模板引用方案时，先核对运行所需的编辑器资产：按钮下有四个直接子级“模板引用控件”，并已分别绑定到“默认状态节点、悬停状态节点、按下状态节点、不可用状态节点”；按需配置按键样式、可被光标射线检测、按钮是否可用和音效。四个引用若同名，应在编辑器中改名后把实际名字写进 CONFIG。点击监听注册在 `ClientUIPresetButtonControl` 本身；Lua 不能创建按键样式或写 `referencedPrefabIndex`。未完成编辑器配置时可继续编写有明确前提和校验的代码。

预设按钮本体不提供图片或文本外观，先检查状态模板是否有可显示内容；空内容按钮在满足输入条件时仍可能被命中，不能用点击响应或模拟点击证明外观已显示。Lua 可按对应类型 API 修改已取得的显示子控件，不能给按钮本体写不存在的图片、文字或颜色字段；详见 [空预设按钮的表现](../docs/10_预设按钮四态与样式.md#空预设按钮的表现)。

- 事件枚举从 §26 逐字复制，不通过拼接猜名字。`KeyboardKeyCode` 用于提示等配置，不等于 `KeyEventType`。
- 持续移动保存 Down/Up 状态，两者配对；单次按下动作只监听 Down 即可。失焦或停用时清空持续按键状态。
- 按键回调返回 boolean；处理了本次事件才返回 true。注销用注册时同一个回调引用，不写新匿名函数冒充原引用。
- 光标监听按官方要求打开所属容器的 `showCursor`，检测目标使用已声明的 `raycastTarget`。不要认为 alpha=0 自动禁用交互。
- `CursorEventData` 的 `touchId` 可用于按玩法记录触点；如果玩法需要防止抬起/点击重复结算，应由脚本按 `touchId` 自己去重。这是实现策略，不是 API 自动保证。
- 判断点了哪个控件优先使用原生事件；坐标边界见 [坐标规则](60_坐标.md)。

设备适配：用 `game.GetDevice()` 判断当前输入设备，再按设备选操作方式——键鼠走光标事件，手柄走焦点与方向导航（文档枚举 + `SetControllerNavigation`）。焦点按需求设置，不假定切换设备一定会发生什么。摇杆返回两个数，需有限数检查、死区与范围约束。

停用时移除自己注册的监听；恢复时不得重复注册。不要调用 RemoveAll 类接口删除其他脚本的监听。
