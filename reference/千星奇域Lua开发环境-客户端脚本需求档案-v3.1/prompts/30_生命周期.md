# 生命周期与资源所有权

先读 [API 正文](../docs/客户端控件API文档.md) §1、§2、§5–§8。回调名称固定，但本文不假定未声明的精确触发顺序。

- `OnInit` 处理不依赖完整控件树的本地状态；`OnStart` 取得宿主和构建内容。
- `OnEnable` 与启动可能衔接，启动函数应幂等，避免重复创建/注册。`OnDisable` 明确暂停或取消本次工作。
- `OnDestroy` 停动画、注销监听、销毁自己创建的控件；重复清理无副作用。
- 简单模板用少量布尔状态或小状态表即可。只有复杂初始化/重连才引入多态状态机。
- 自己创建的控件由自己销毁；`script.object` 和找到的已有控件属于借用，不销毁。
- 保存 Tween/Sequence、监听回调引用，结束时释放引用；长期交互不能让句柄数组无限增长。
- 多资源按依赖逆序清理：先关输入和动画，再销毁控件。逐项保护清理，某项失败仍尝试剩余项，保留首错。

## 启动失败分类

| 情况 | 处理 |
|---|---|
| 未填值、类型不符、确定挂错脚本/节点 | 立即报明确错误，不做几百帧无意义重试 |
| 文档或项目约定说明依赖会稍后就绪 | 才用有界重试；预算、触发入口和停止条件写清 |
| API 调用异常、构建失败 | 停止业务，清理部分创建的资源，报告原错误 |

`pcall(fn)` 的第一个返回值仅表示“是否抛错”。若 `fn` 返回 `false, reason`，要接成 `callOk, ready, reason` 分别判断，不能用 `if callOk then` 当“启动成功”。

异步完成回调应检查脚本/控件仍存活，且本次演出代号仍有效。退出时先作废代号再 `Kill(false)`，防止旧回调恢复已关闭界面。
