# 预设按钮：四态模板引用与按键样式

`预设按钮`是编辑器里的复合控件。它的视觉状态由界面配置和模板引用组成，Lua 主要负责找到按钮、接收光标事件、控制可交互状态和清理监听。

先按 [按钮术语与防混淆清单](08_控件名称与CONFIG配置.md#按钮术语与防混淆清单) 区分结构：需要自定义交互时可采用 [组合式按钮](08_控件名称与CONFIG配置.md#组合式按钮推荐结构)，需要编辑器管理四态、按键样式或点击音效时采用本文的预设按钮控件。预设按钮不等于“静态按钮”；已有预设按钮需要换图、改字或 Tween 时，先核对相应显示子控件或基类接口，不必因此改成组合式按钮。

这份说明补足 API 表没有展开的编辑器准备步骤：

- 官方指南明确预设按钮支持四种状态的图标、文本、节点显隐、关联按键和点击音效。
- 用户提供的界面截图补充了组成方式：每个状态槽位只放一个控件。若当前面板使用模板引用方案，按钮下的四个直接子级是 `模板引用控件`；每个引用控件只设置一个 `referencedPrefabIndex`。被引用的模板是模板库中另行保存的控件，不是按钮层级中该引用控件的子节点。
- API 文档只保证 `ClientUIPresetButtonControl` 的运行时接口，以及 `ClientUIReferenceControl.referencedPrefabIndex` 的只读访问；它没有声明 Lua 可以创建按键样式或写入引用索引。本包也不在 API 正文里追加这一段说明。

因此，四个引用和按键样式属于**编辑器前置条件**，不能用 Lua 代码代替。槽位本身只接受一个控件；需要复数控件拼合时，应在模板库中另存一个以 `容器节点` 为根的模板，并把图片、文本框等内容放在该模板内部。按钮层级只放模板引用控件，再为每个引用填写对应的单个模板索引。

## 空预设按钮的表现

预设按钮本体不提供图片或文本外观。[API 正文](客户端控件API文档.md) §17 列出的**专有字段**只有 `interactable`、`clickAudioId`、`raycastTarget`，没有图片、文本或颜色字段；§12–13 同时说明它继承控件基类，因此仍有布局、变换和显隐等能力，不能把“没有图片或文本外观字段”说成“完全没有可视相关能力”。[官方控件图册的预设按钮一节](../guides/官方客户端控件详见图册.md#detail-8) 说明：“状态外显样式来自子层级客户端控件”。

据此检查外观和输入时，要区分两件事：

1. **没有显示内容，就没有按钮外观来源。** 当前状态没有绑定可显示的子控件，或引用模板中没有可显示内容时，按钮本体不会自动绘制背景、文字或边框。只有部分状态漏配时，可能只在切换到相应状态后缺失外观，不能笼统断言“四态没配齐就始终完全不可见”。按本文的模板引用方案，先在编辑器中做好四个状态模板的图片、文本框等内容，再绑定对应引用和状态槽位。
2. **没有外观，不等于不能被命中。** 当 `raycastTarget=true` 且满足容器、光标、区域等输入条件时，没有显示内容的按钮仍可能参与光标命中。命中是否产生点击事件还需核对可交互状态等条件；不能只凭 `raycastTarget=true` 保证点击成功，也不假定它的默认值。收到点击回调只说明事件路径有响应，不能证明图标、文字或四态外观已经显示；模拟点击同样不能证明实际光标命中或画面显示。

Lua 不能通过给按钮本体写 `text`、`imageColor` 等不存在的字段来补外观，也没有本包文档声明的四态槽位写入接口。不过，取得实际的图片或文本子控件后，可以按其类型 API 修改内容，例如使用图片控件的 `SetImage`、`imageColor` 或文本框的 `text`、`fontColor`（API §14–15）。因此不能写成“Lua 无法修改任何按钮外观”；需要区分**编辑器中的状态绑定**与**显示子控件的内容更新**。

上述字段、继承关系和样式来源属于文档依据；空内容及命中风险是据此给出的条件性判断（`inferred`），不代表已在当前工程运行观察。四个引用存在或点击日志出现，都不能作为外观验证通过的证据。

## 编辑器中先做什么

按下面顺序准备一个按钮。名称是示例角色名，不是编辑器自动生成的正式默认名；实际名字以当前工程显示为准。

1. 在客户端控件容器或客户端控件模板中创建一个 `预设按钮`。索引由当前工程产生，本包不给出示例数值。
2. 为四个状态各准备一个模板。需要组合图片、文本框等内容时，在模板库中分别保存以 `容器节点` 为根的状态模板；这些模板与预设按钮不在同一个层级树中。然后在预设按钮下面创建四个直接子控件，类型都选 `模板引用控件`，每个引用只填写一个对应的模板索引。四个引用分别承担：

   按钮层级示意（名称仅为示例）：

   ```text
   预设按钮
   ├─ 模板引用控件_默认
   ├─ 模板引用控件_悬停
   ├─ 模板引用控件_按下
   └─ 模板引用控件_禁用
   ```

   模板库中的独立结构示意：

   ```text
   默认状态模板根（容器节点）
   ├─ 图片
   └─ 文本框
   ```

   | 按钮设置中的正式槽位 | 作用 | 建议在 CONFIG 中使用的键 |
   |---|---|---|
   | 默认状态节点 | 默认显示 | `default` |
   | 悬停状态节点 | 光标或手柄聚焦时显示 | `hover` |
   | 按下状态节点 | 按住或点击按下时显示 | `pressed` |
   | 不可用状态节点 | `interactable=false` 时显示 | `disabled` |

   编辑器可能使用别的状态称呼或自动名称。四个引用如果都叫“模板引用控件”，请在编辑器中改成四个不同的实际名称，再把名称填入 CONFIG；不要把 `default`、`hover` 等逻辑键当成 `GetChild` 的默认名称。

3. 在预设按钮的“按钮设置”中，把四个模板引用分别放入“默认状态节点”“悬停状态节点”“按下状态节点”“不可用状态节点”四个槽位，并为每个引用设置一个对应的模板索引。然后按需要设置“可被光标射线检测”“按钮是否可用”和音效。四个槽位只保存四个引用入口；模板内部的子控件数量由模板本身决定。
4. 保存并登记控件组或模板，使当前工程能够读取引用配置。`referencedPrefabIndex` 只是 API 声明的只读诊断字段；不要把运行时 `id`、图片 `imageId` 或脚本映射 ID 填进这里。
5. 确认预设按钮和父级客户端容器已激活、可见。需要光标事件时，按 API 要求让所属 `ClientUIContainerControl.showCursor=true`，并让按钮的 `raycastTarget=true`。

编辑器里需要设置的项：四个模板的内容、四个引用各自的单个模板索引、四个状态节点槽位、`可被光标射线检测`、`按钮是否可用` 和音效。索引由当前工程产生，本包不给出示例数值。

如果四个引用没有放在预设按钮的直接子级，`button:GetChild(name)` 找不到它们；如果当前状态未绑定可显示内容或模板内容为空，相应状态可能没有外观。按钮本体不保证提供默认外框。两种情况都先回到界面编辑器核对结构、状态绑定和模板内容，不在 Lua 中猜索引。

## Lua 中查什么、改什么

脚本必须挂在按钮父级的 `ClientUIContainerControl`（简中名称为“容器节点”）上，才能按 API 要求设置 `showCursor`；不要把本示例直接挂在预设按钮本体。脚本按实际名称查找按钮和四个引用。四个引用只用于结构检查或后续读取；点击监听应该注册在 `ClientUIPresetButtonControl` 本身。

```lua
-- 前提：容器节点的直接子级有一个“预设按钮”；
-- 预设按钮的直接子级有四个已绑定样式的“模板引用控件”。
local CONFIG = {
    BUTTON_NAME = "预设按钮",
    STATE_REF_NAMES = {
        default = "模板引用控件_默认",
        hover = "模板引用控件_悬停",
        pressed = "模板引用控件_按下",
        disabled = "模板引用控件_禁用",
    },
}

local host, button, stateRefs, clickCallback = nil, nil, {}, nil
local enabled = false

local function clearRefs()
    stateRefs = {}
end

local function prepare()
    host = script.object
    if host == nil or not host.alive then return false end

    -- host 必须是按钮的父级客户端容器；showCursor 是容器字段。
    host.showCursor = true
    button = host:GetChild(CONFIG.BUTTON_NAME)
    if button == nil or not button.alive then return false end

    for role, childName in pairs(CONFIG.STATE_REF_NAMES) do
        local reference = button:GetChild(childName)
        if reference == nil or not reference.alive then
            printerr("[预设按钮] 缺少四态模板引用控件：" .. tostring(role))
            return false
        end
        stateRefs[role] = reference
    end

    -- raycastTarget、interactable 和音效沿用编辑器设置。
    -- 不在这里强制写 true，否则会覆盖不可用状态的测试配置。
    return true
end

function OnStart()
    if not prepare() then
        printerr("[预设按钮] 请先完成四个模板引用和按键样式配置")
        return
    end
    enabled = true
    clickCallback = function(eventData)
        if not enabled then return end
        print("[预设按钮] CursorClick")
        -- 在这里调用自己的玩法函数或发送信号。
    end
    button:AddCursorEventListener(Enum.CursorEventType.CursorClick, clickCallback)
end

function OnDisable()
    enabled = false
    if button and button.alive and clickCallback then
        button:RemoveCursorEventListener(Enum.CursorEventType.CursorClick, clickCallback)
    end
    clickCallback = nil
end

function OnDestroy()
    OnDisable()
    clearRefs()
    button, host = nil, nil
end
```

`referencedPrefabIndex` 是 `ClientUIReferenceControl` 的只读字段，只能读取来打印或诊断，不能这样写：

```lua
-- 错误：API 文档把它列为只读；按键样式必须在界面编辑器中配置。
reference.referencedPrefabIndex = 123456
```

同样，不要在 Lua 中假造四个模板索引来“补齐”按钮。模板索引的来源、父级和保存状态必须来自当前工程的界面控件组管理。

## 与光标检测区域的区别

预设按钮控件通常直接监听它的 `CursorClick`。组合式按钮则使用容器节点下的 `光标检测区域` 接收事件，再由 Lua 改变同一容器下的图片、文本框或其他内容。两者按结构区分，不按画面是否变化区分；不要把组合式按钮的命中区域当作预设按钮的四态样式内容。

采用组合式按钮时，把光标检测区域作为按钮的命中层，并按它自己的 `raycastTarget` 和父级 `showCursor` 规则配置。沿用本文的四态模板引用方案时，不要因为看见“可点击图片”就把四个模板引用改成四个图片控件；这不表示所有预设按钮都只能使用该模板引用方案。

## 自检和证据边界

| 检查项 | 结果含义 |
|---|---|
| 四个状态模板均有预期的图片、文本框等显示内容 | 外观来源检查；引用存在不代表模板内容非空或画面可见 |
| 按钮有四个直接子级模板引用控件 | 编辑器结构前提；本包不把状态名硬编码成官方默认名 |
| 每个引用已绑定到按键样式 | 编辑器配置前提；Lua 只能读取引用索引，不能写样式 |
| `ClientUIPresetButtonControl` 的字段和监听 | `K1 / documented`，查 API §17 |
| 四态子节点组成 | `K3 / provided_unverified`，由用户提供的编辑器截图补充；官方指南只明确四态表现，没有给出完整子树表 |
| 点击回调有响应 | 只证明事件路径有响应；不证明按钮外观显示或四态切换正确 |
| 游戏中实际显示与切换画面 | 未观察时为 `pending`；直接画面观察或用户明确确认可记录对应结果，单纯点击日志不能代替 |

本文不把四态槽位编号或通用模板索引写成 API 事实，四态绑定以当前编辑器的预设按钮面板为准。四态是否真的在运行时切换，需要用户在自己的工程里观察后另行确认。

遇到按钮无显示、状态不切换或点击无响应时，按问题检查：

1. **外观与状态：** 四个状态模板的内容是否为空、当前状态是否有预期的图片或文本、四个引用是否为直接子级、各引用索引及状态槽位是否正确绑定；再检查按钮、显示子控件和父级的激活/可见状态，以及资源、尺寸、透明度和裁剪。不要假定按钮自带边框。
2. **输入与事件：** 所属容器的 `showCursor`、按钮 `raycastTarget`、`interactable`、命中区域与遮挡，以及监听是否正确注册或重复注册。点击有响应后，外观检查仍须独立记录，不能因此标记“按钮已显示”。

未在当前工程观察的显示和命中行为保留为待确认，不要求先试玩才能继续完成有依据的代码。不要先改 Lua 索引。
