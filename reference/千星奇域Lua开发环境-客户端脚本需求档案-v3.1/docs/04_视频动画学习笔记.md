# 视频动画逻辑：纯文本查询册

本册面向 AI 查询，不包含截图、视频链接或图册入口。来源编号 `REF-VIDEO-INTRO` 为控件与脚本演示，`REF-VIDEO-TWEEN` 为 44 页动画教学；按清晰标题、代码和页码整理，内容来自原神 7.1 创作者体验服。示例不是当前项目默认配置，也不替代 `客户端控件API文档.md`。

证据分开使用：`video_observed` 表示来源视频画面出现过，不属于当前项目的 K4 客户端观察；`documented` 表示当前 API 明确声明；`inferred` 表示依据前两者提出的编排方法；`unknown` 表示没有足够证据。本册列出的调用与字段已交叉核对 API；项目实际布局、资产和运行结果仍不能由视频推定。

## 1. 先判断对象、属性与时间

补间输入为“控件实例 + 目标字段表 + 持续时间”。控件模板索引用于创建实例；图片资产 ID 用于设置图片；两者都不是 Tween 的目标对象。生命周期、创建流程、ID 取值分别按 `00_开始之前.md`、`01_API阅读与防混淆.md`、`02_图片资产ID索引.md` 核对。

视频中的动态创建图片示例采用以下顺序：

```text
脚本映射挂到容器节点
→ OnStart 中取得 script.object
→ game.InstantiateClientUIControl(自己的模板索引, 父控件)
→ SetImage(已确认的图片来源, 自己的图片ID)
→ 设置激活/可见性与初始位姿
→ 准备目标表
→ game.Tween(实例, 目标表, 时长)
→ SetRelative、SetEase
→ Play
```

这只是动态创建图片的一种写法。已有控件可按层级用 `GetChild` 或 `FindChild` 取得；图片已配置时不必再调用 `SetImage`。脚本按需求挂载到 API 支持的控件上，不要求所有方案都先创建容器或动态生成控件。

`game.*` 用点号；控件、Tween、Sequence 实例方法用冒号。`SetActive` 会影响可见性与挂载脚本运行；`SetVisible` 只改变可见性。不要对只读的 `active`、`visible` 直接赋值。目标字段须同时满足：该控件拥有、允许写入、明确标注 Tweenable。

视频流程包含“保存后试玩”，它是作者的演示步骤，不构成本包强制真机验收条件。优先完成文档回查、静态结构检查与已有知识约束；需要额外确认视觉表现时才提供可选观察项。

## 3. 常见动画的编写约束

### 位移、尺寸、旋转

- `anchoredPositionX/Y` 与父级和锚点有关。起点和目标应使用同一坐标关系；不要把画布坐标直接写到父容器局部位置。
- `localScaleX/Y/Z` 是倍率；`sizeDeltaX/Y` 是布局尺寸参数。视频宽高示例先将最小/最大锚点固定为同一点，不能把其数值解释推广到所有拉伸布局。
- `SetPivot` 确定旋转与缩放的基准。X/Y 旋转的投影、裁剪与镜像外观属于布局相关行为；API 没明确时保持 unknown。
- `SetRelative(false)` 使用绝对目标；`true` 使用相对当前值的增量。反复播放或布局刷新优先明确最终位姿，避免意外累积偏移。

### 颜色、淡入淡出

`Color(r,g,b,a)`、`Color.FromRGB`、`Color.FromRGBA` 与 `Color.ToRGBA` 都在 API 中有声明；通道范围为 0–255。视频颜色页使用 `Color(...)`。只想淡出时保留原 RGB，仅改 alpha；透明不等于停用或禁止交互。

```lua
-- image 已是当前项目的图片控件实例。
local r, g, b = Color.ToRGBA(image.imageColor)
local fade = game.Tween(image, {
    imageColor = Color.FromRGBA(r, g, b, 0),
}, 0.3)
fade:SetRelative(false)
fade:Play()
```

### 填充与羽化

先直接配置模式/开关，再 Tween 数值字段。视频填充配置为 `enableMask = true`、`reverseMaskArea = false`，模式方法设置初始进度 0，再把 `fillAmount` 变到 1。90 度方向枚举为 `ImageFillRadial90Type`，180/360 度为 `ImageFillRadialType`，不可互换。

羽化还开启 `enableSoftEdge`。清晰代码的模式如下，优先于自动转写中可能出错的口播：

| 目标 | 视频的前置配置（示例值，不是默认值） |
|---|---|
| `softEdgeWidthX/Y` | `softEdgeMode = Enum.ImageMaskSoftEdgeMode.Pixel`；`SetSoftEdgeWidth(1,1)`，单方向动画到 80。 |
| `horizontalSoftRange` / `verticalSoftRange` | `softEdgeMode = Enum.ImageMaskSoftEdgeMode.Percentage`；宽度 `(0.05,0.05)`，两范围初值 0.2，单方向动画到 10。 |

API 未声明的全部有效范围、边界钳制、组合效果不得仅据这些演示数值补猜。

### 缓动、并行与序列

- 相同起点、终点、时长，换缓动会改变中途速度。Back/Elastic 可能越过目标，应给全过程预留视觉空间。
- 多字段同一时长、同一缓动：放进一个 Tween 的目标表。
- 先后动作：分别创建 Tween，依次 `Append`，最后播放 Sequence。串行时长为各步骤之和。
- 不同时长/缓动的并行动作可查 API 的 `Join`；它与当前队尾步骤同时开始，以最晚结束者为准。该语义来自 API，不能说第二视频展示了完整 Join 源码。
- 等待查 `AppendInterval`；末尾动作查 `AppendCallback`；指定时间查 `Insert`/`InsertCallback`。

```lua
-- 独立改写的结构示例，坐标/时长由本项目自行选择。
image:SetAnchoredPosition(20, 0)
image:SetLocalScale(1, 1, 1)
local move = game.Tween(image, { anchoredPositionX = 220 }, 1)
local grow = game.Tween(image, { localScaleX = 1.2, localScaleY = 1.2 }, 0.2)
move:SetRelative(false)
grow:SetRelative(false)
move:SetEase(Enum.EaseType.Linear)
grow:SetEase(Enum.EaseType.OutSine)
local sequence = game.TweenSequence()
sequence:Append(move)
sequence:Append(grow)
sequence:Play()
```

以上只是演出片段。完整脚本保存 Tween/Sequence 引用，开始替代动作前 `Kill(false)`，并在停用、销毁时清理；完成回调检查对象 `alive` 与当前演出状态。不要让逐帧逻辑和 Tween 同时控制同一字段。卡牌演出细节见 `03_卡牌Tween演出配方.md`。

## 4. API 字段清单

| 控件范围 | 已记录的 Tweenable 字段 |
|---|---|
| 所有具体控件共有 16 项 | `anchoredPositionX/Y`、`sizeDeltaX/Y`、`anchorMinX/Y`、`anchorMaxX/Y`、`pivotX/Y`、`localScaleX/Y/Z`、`localRotationX/Y/Z` |
| 图片专有 6 项 | `imageColor`、`fillAmount`、`softEdgeWidthX/Y`、`horizontalSoftRange`、`verticalSoftRange` |
| 文本框、文本视窗各专有 5 项 | `fontSize`、`minimumFontSize`、`fontColor`、`bgColor`、`outlineColor` |
| 网格视窗专有 1 项 | `scrollProgress` |

`text`、`imageId`、图片类型、填充模式、羽化开关及激活/可见状态不属于上述 Tweenable 字段，不能因“可以设置”就放入 Tween 表。类型专有字段不能用于别的控件。

`scrollProgress` 是归一化进度：`0` 是起点、`1` 是末端。`客户端控件API文档.md` §20 只写“滚动进度、Tweenable”未给范围；包内统一按 `[0, 1]` 处理 —— 写入前夹取（`math.max(0, math.min(1, v))`），读回时按同一区间判断。与 `16_网格背包动态列表与拖拽配方.md` 的用法一致。

显隐不放进 Tween 表。`visible` 是只读字段（API 正文 §13），修改可见性只能调用 `SetVisible(visible)`（同节）；`SetVisible` 只改可见性，不改变激活状态，也不停止脚本逻辑。因此“到某个时间点就显示/隐藏”这类需求直接用 `SetVisible(true/false)` 写入，不要写进 `game.Tween` 的目标表。

EaseType 共 31 个：`Linear`；`Sine`、`Quad`、`Cubic`、`Quart`、`Quint`、`Expo`、`Circ`、`Back`、`Elastic`、`Bounce` 十个家族分别加 `In`、`Out`、`InOut` 前缀。正式拼写须按枚举表回查。

## 5. 第一视频提供的整体逻辑

- 容器组织父子关系；演示三元素随父容器整体移动。模板引用复用设计，同级顺序改变前后显示关系，这些都不同于 Tween 的位置参数。
- 输入和状态触发可见反馈；图片、文本、按钮、网格视窗各有职责。图片位移 Tween 与播放预先配置的界面/全屏动效资源是不同能力。
- “星光快递”按出发、变装、到达组织演出，变装时颜色与大小同时变化；画面展示效果，未给出完整源码。
- 绕行演示强调逐帧、暂停/继续和资源管理。API 明确 `OnUpdate` 不受关卡时停影响、`OnLevelUpdate` 受影响；不能据此推定 Tween 的时停行为。
- 信号与变量页面的这次演示只在客户端进行；不证明服务器信号、多人同步或玩法判定已经实现。

## 6. 自我约束与未确认事项

创作前只需先写：对象是谁、改哪些字段、起终点、时长、哪些同时/先后发生、何时结束/取消。按这些事实选择已有 API，完成 `05_知识层级验证与Debug.md` 的自检，不把未知项转嫁成默认的真机任务。

仍属 unknown 或视频未完整提供：编辑器每步具体菜单名；作者完整源码和异常分支；示例 ID 在本项目是否存在；所有布局/裁剪组合的外观；Tween 自动释放和时停细节；多个 Tween 写同字段的优先级；羽化参数未声明的全部合法范围。遇到它们先缩小方案到已确认能力，再说明可选的局部观察，不声称“当前项目已运行通过”。
