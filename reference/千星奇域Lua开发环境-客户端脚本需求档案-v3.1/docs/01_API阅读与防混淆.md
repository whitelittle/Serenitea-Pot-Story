# API 阅读与防混淆

这份文档规定“如何确认一个写法能不能用”。它不新增 API，也不替代 [`客户端控件API文档.md`](./客户端控件API文档.md)。

## 1. API 事实的唯一来源

- **唯一权威**：`docs/客户端控件API文档.md`。函数、方法、字段、类型、参数、返回值、枚举值、字段读写性和生命周期，都必须回到这份文档确认。
- **只负责定位**：`docs/本地API索引.md` 可以告诉你章节和行号，但索引中的摘要不能代替完整定义。
- **只能当线索**：`templates/`、创作者提供的脚本、存档样本和模型记忆可以帮助发现关键词；它们不能证明 API 存在，也不能证明某个行为已经验证。
- **编辑器操作**：客户端控件和脚本如何创建、挂载、保存，查 [`千星沙箱客户端脚本使用指南.md`](./千星沙箱客户端脚本使用指南.md)。

当前包内 API 文档和官方使用指南没有给出 Lua `require` 的模块路径语法；指南明确的是脚本映射与本地文件的上传关系。OOO 公开关卡资料只能作为模块组织的**可选外部结构参考**，不记录其运行状态，也不是本包的运行依赖。多文件模板的新目录与映射组合仍需单独说明条件，不能据此写成“任意路径官方均支持”。

`normalizeName` 是普通 Lua 辅助函数，用来清理或比较文件名。当前 `templates/01–08` 与 `templates/multifile/core/runtime.lua` 共 9 个文件都用它；API 文档没有把它列为宿主能力，OOO 资料也不是以前置条件。`EXPECTED_SCRIPT_NAME = nil` 时可以连同校验分支一起删除。它只能减少文件名比较的误报，不能解决脚本加载时序，也不能代替脚本映射检查。

如果 API 文档被替换或版本不明，旧结论全部降级为 `unknown`，重新查证后再写代码。

## 2. 每个 API 的查阅步骤

在代码中第一次使用某个 API 前，按下面顺序做一张小卡片。只要有一项找不到，就不要凭经验补全。

1. 用 `本地API索引.md` 找到所属章节；大文件只按关键词定向检索。
2. 回到 `客户端控件API文档.md`，从章节标题读到该章节结束，不能只看命中行。
3. 记录完整签名：所属对象、点号或冒号、参数顺序和类型、返回值。
4. 记录字段是“只读”还是“读写”，以及是否注明 `Tweenable`。只读字段不能赋值，未列为可补间的字段不能放进 `game.Tween` 的目标表。
5. 记录枚举的**完整名称和值**。不要把中文描述改造成自创枚举，也不要把其他引擎的枚举名套进来。
6. 记录调用时机：对象何时出现、是否要求 `alive`、容器是否必须激活、何时释放监听和 Tween。
7. 在交付前逐个回查代码里的标识。未命中的标识数量必须为零；不确定的行为写成 `unknown`，不要用“应该可以”掩盖。

推荐的核对表：

| 项目 | 要填的内容 |
|---|---|
| 标识 | 文档中的精确名称和章节 |
| 形式 | `对象.函数(...)` 还是 `对象:方法(...)`；字段访问用点号 |
| 参数 | 顺序、类型、必填/可选 |
| 返回 | 返回类型、是否多返回值、是否可能为空 |
| 字段 | 读写性、可补间性、数值范围 |
| 枚举 | 完整枚举名和值 |
| 生命周期 | 创建、激活、禁用、销毁时能否调用 |
| 清理 | `Kill`、注销监听、销毁控件等动作和拥有者 |
| 证据 | `documented`、`static_checked`、`provided_unverified`、`user_confirmed`、`video_observed`、`inferred`、`observed`、`unknown`，并与真机状态分开 |

## 3. 点号、冒号和返回值

Lua 的点号和冒号不是装饰：

- 文档写 `game.Tween(object, data, duration)` 时，它是函数调用，使用 `game.Tween(...)`。
- 文档写 `Tween:SetEase(easeType)` 时，它是实例方法，使用 `tween:SetEase(...)`，Lua 会传入实例自身。
- 文档写字段（例如控件的 `imageId`、`prefabIndex`）时，先确认访问权限再读取或赋值；不要把字段当成方法调用。
- 文档声明多返回值时，要按文档顺序接收。不要把一个对象猜成坐标表，也不要把 `nil` 当成合法控件。

`pcall` 只能保护**已经在文档中找到的调用**，用于把故障转成可读日志；它不能把不存在的函数“试出来”，也不能替代签名核对。

## 4. 容器节点索引与控件模板索引

这两个是最容易被口头混成“索引”的东西，取法不同，用途也不同。

**容器节点索引（挂载用）**

在【界面控件组管理】的【界面布局】里新增或选一个【客户端控件容器】，右侧 inspector 的【画布设置】点【前往编辑】，打开这个容器；容器里预设会有一个父节点，它就是**容器节点**。选中它，读它的**容器索引**。

`容器节点`是单独的控件类型（API 正文继承关系表里是 `ClientUIContainerControl`，另有独立章节）。脚本挂在容器节点上，动态创建的实例也以它作父节点。容器节点索引用于脚本挂载与交接，**不是**控件模板索引。

> 证据：控件类型与字段名是 `K1 / documented`（见 API 正文）。**「选中容器节点读容器索引」这条取法来自创作者确认的编辑器界面**，官方指南没有逐步写出这一步，记为 `K3 / user_confirmed`。

**控件模板索引（实例化 / 身份核对用）**

所有模板都在【界面控件组管理】→【界面控件组库】→【客户端控件模板】里。新建并另存模板，或点开已有模板，都会进到【界面控件组详细】，右侧 inspector 面板的**控件名字下方**显示该控件的**控件索引**，也就是 `controlPrefabIndex`（控件模板索引）。脚本侧 `game.InstantiateClientUIControl(controlPrefabIndex, parent)` 收的就是它。

**五个称呼对照（写代码时不能混用）**

| 名称 | 文档里的精确字段或接口 | 由谁产生 | 用途 | 不能拿来当 |
|---|---|---|---|---|
| 容器节点索引（容器索引） | 无 Lua 字段；交接用的编辑器编号 | 编辑器画布中【客户端控件容器】里的容器节点 | 确认脚本挂载在哪、动态实例以谁为父节点 | 控件模板索引 |
| 控件模板索引 | `ClientUIBaseControl.prefabIndex`（只读）；创建入口 `game.InstantiateClientUIControl(controlPrefabIndex, parent)` | 【客户端控件模板】里保存的模板 | 创建模板实例、核对模板身份 | 运行时控件 ID；不存在通用的按 `prefabIndex` 获取现有实例接口 |
| 运行时控件 ID | `ClientUIBaseControl.id`（只读，运行时 ID）；查找入口 `game.GetClientUIControl(controlId)` | 客户端运行时 | 按运行时身份查找实例 | 控件模板索引 |
| 图片 ID | `ClientUIImageControl.imageId`（只读）；与 `imageSource` 配对 | 图片资源 | 指定图片内容 | 控件或模板身份 |
| 脚本映射 ID | `Script.scriptMappingId`（只读） | 客户端脚本资源管理器 | 识别脚本映射 | 挂载节点索引 |

表格里列的字段名与调用形式都以 [API 正文](./客户端控件API文档.md) 为准；「容器节点索引」在 Lua 侧没有对应字段，它只用于交接与挂载核对。

写代码时用文档里的精确字段名，不要用“索引”“ID”“编号”这类口头说法代替。`ClientUIBaseControl.prefabIndex` 是只读的控件模板索引，只说明模板身份，不说明实例身份；同一个模板索引可以在不同父级下出现多个实例。已有实例优先使用创建返回值、运行时 `id`、名称或路径；按 `prefabIndex` 递归扫描只能作为当前父级内确认唯一时的诊断策略，不是 API 提供的通用查找方法。

**不要把元件 ID 和控件索引扯在一起。** `ServerSignal:AddPrefabId(...)` 里的元件 ID 是给服务器节点图参数用的；Lua 侧没有直接与实体元件交互的能力。两者名字像，来源、作用域和可用范围都不同。

## 5. API 文档中容易混淆的地方

| 易混点 | 约束 |
|---|---|
| 同名方法来自不同类型 | 先确认目标控件类及继承关系，再读该类的字段/方法；不要把图片控件专用字段写给容器节点。 |
| `active` / `visible` | 字段为只读时，使用文档声明的 `SetActive` / `SetVisible`；二者对脚本运行的影响不同。 |
| `imageId` / `imageSource` | 两个字段为只读，修改图片使用 `SetImage`；来源与 ID 必须成对记录。 |
| 容器节点 / 动态模板 | 只有文档允许的模板父节点可动态创建；画布节点和模板子节点不能因为“也有索引”就获得创建资格。容器节点索引只用于挂载。 |
| Color 数值范围 | 使用本 API 文档规定的 0–255 颜色通道，不套用其他库的 0–1 范围。 |
| `EnableUpdate` / `EnableTick` | 当前 API 文档声明 `script:EnableUpdate`；旧名、注解或样本不能新增 `EnableTick`。 |
| `printerr` / `error` | `printerr` 只写错误日志，不会抛出异常或终止执行；故障分支需要显式返回或改变状态。 |
| Tween 的 `Kill` / `Complete` | 取消表现不能依赖“自动结束”；先读方法对最终状态和回调的说明，再选择取消或完成。 |
| 表中的 `—` 返回值 | 不能继续链式调用；新手模板优先每行一条方法调用。 |
| 容器光标与光标区域 | `showCursor` 属于 ClientUIContainerControl；光标区域负责监听，不能跨类型使用同名概念。 |
| 视频和样本的证据 | 视频画面用 `video_observed`；用户确认的原工程用 `user_confirmed`；均记录范围，不冒充本次目标环境观察。 |
| 文档没有的能力 | 不根据 Unity、浏览器或其他 Lua 框架补出定时器、坐标换算、自动暂停等隐含行为。 |

## 6. 对控件和动画的最低约束

写控件逻辑前，先得到一个明确的引用，并按文档确认：

- 引用不为 `nil` 且对象仍 `alive`；
- 父级客户端控件容器已激活且可见；
- 需要写入的字段确实是读写字段；
- Tween 的目标字段在文档中明确标记为可补间；
- 同一时刻不会有两条 Tween 争夺同一对象的同一字段；新动画开始前停止旧动画；
- 每个 Tween、监听器和动态控件都有唯一拥有者，并在禁用/销毁时清理。

这些是代码自我约束，不要求创作者在每次创建控件后立即进行真机操作。

## 7. 不确定时如何回复

遇到以下任一情况，结论标为 `unknown`，停止依赖该能力的实现，并说明需要的最小信息：

- API 文档没有该标识；
- 文档只出现名称，没有签名、参数或读写性；
- 同一目标版本的权威定义互相冲突且尚未解决（样本与正文有差异时先分清版本、类型、工程扩展，不否定已确认的原工程运行事实）；
- 需要的坐标、资产来源、枚举值或生命周期条件没有依据；
- 只能靠“试玩看看”才能猜出行为。

回复可以这样写：

```text
API: <标识>
证据: unknown（在 docs/客户端控件API文档.md 未找到完整定义）
影响: 暂停 <哪一段实现>
需要: <创作者提供的最小文档片段或明确的编辑器信息>
```

不能把 `unknown` 改写成“真机待确认后大概率可用”。

## 8. 交付前回查

交付前从 Lua 文件提取所有宿主 API 标识，逐条对照 API 文档，并同时检查：

- 点号/冒号没有混用；
- 字段读写性没有违反；
- 数值、颜色和枚举来自文档；
- ID 类型有明确变量名（如 `containerNodeIndex`、`prefabIndex`、`imageId`）；
- 资源清理路径覆盖正常结束、禁用和销毁；
- 每个结论的证据来源和真机状态分开报告。

静态检查完成即可交付代码草稿。真机验证只有在创作者主动要求确认运行行为，或文档明确要求观察时才安排。
