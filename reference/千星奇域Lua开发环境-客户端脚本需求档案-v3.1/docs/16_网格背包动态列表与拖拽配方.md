# 网格背包：动态列表、拖拽预览与滚动位置

这份方案把网格背包的动态列表、拖拽预览和滚动位置整理成独立可迁移的写法。它不是某个存档或运行结果的复制品；所有索引、运行时 ID、图片 ID 和信号名都必须换成当前工程自己的值。API 事实仍以 [`客户端控件API文档.md`](客户端控件API文档.md) §6、§9、§13、§14、§18–§20、§24 为准。

## 1. 编辑器准备

先在【界面控件组管理】中保存一个**可实例化的列表项父节点**，例如“容器节点_物品项”。它的直接子级可以是：

- `图片`：显示道具图标；
- `文本框`：显示名称或数量；
- `光标检测区域`：接收这一项的光标事件。

另存一个用于拖拽预览的模板。若列表项的根本身是图片，也可以用图片根模板作为幽灵；若模板包含检测区域，创建后要把幽灵区域设为不可射线检测，避免幽灵挡住真实列表项。主界面中预先放置一个正式名称为“网格视窗”的控件，并把列表项尺寸、方向、间距和射线检测配置好。

`CONFIG` 至少要有以下来源明确的值：

| 配置 | 从哪里取得 | 不能混用 |
|---|---|---|
| `GRID_NAME` | 网格视窗在画布中的正式名称 | 容器节点索引、运行时 `id` |
| `ITEM_PREFAB_INDEX` | 保存后的列表项父模板索引 | 列表项实例的 `id` |
| `DRAG_GHOST_PREFAB_INDEX` | 保存后的拖拽预览模板索引 | `imageId` |
| `ITEM_IMAGE_NAME` 等 | 列表项模板的直接子级名称 | 英文猜名或相对路径 |
| `IMAGE_ID` | 图片资产清单或编辑器资产面板 | 控件模板索引 |
| `REQUEST_SIGNAL_NAME` | 服务器节点图约定；没有就留 `nil` | 任意自造信号名 |

列表项模板索引只写到网格的 `itemPrefabIndex`。网格项不使用 `game.InstantiateClientUIControl` 创建；普通面板和拖拽幽灵才使用该函数。

## 2. 正确的创建顺序

全局脚本可能比普通 UI 控件组更早加载，所以不要在 `OnStart` 只试一次。可以在有限次数的 `OnUpdate` 中等待：

1. 取得脚本宿主和网格，并确认 `alive`、`activeInHierarchy`；
2. 将容器节点的 `showCursor` 设为 `true`，再设置 `grid.itemPrefabIndex`、`raycastTarget` 和 `interactable`；
3. 用一次小容量 `RefreshItems` 探测回调和 `GetItemIndex`；
4. 确认回调返回的是 `ClientUIContainerControl`（或当前模板实际根类型）；
5. 用正式容量再次 `RefreshItems`，在每个回调里刷新内容并注册事件；
6. 回调完成后恢复之前保存的 `scrollProgress`。

等待必须有上限。到达上限只记录“模板未登记、UI 尚未激活或加载失败”，不要继续穷举任意整数索引。`itemCount` 是只读结果；它不等于模板索引。

## 3. 每一个列表项都要绑定事件

事件监听属于列表项内部的 `光标检测区域`，不是只给网格根注册一次。虚拟化列表会复用控件，所以每次 `RefreshItems` 回调都要：

1. 通过 `item:GetChild("图片")`、`item:GetChild("文本框")`、`item:GetChild("光标检测区域")` 取得直接子级；
2. 读取 `grid:GetItemIndex(item)`，不要猜回调索引从 0 还是 1 开始；
3. 为该项注册 `CursorEnter`、`CursorExit`、`CursorDown`、`CursorUp`、`CursorClick`、`CursorBeginDrag`、`CursorDrag`、`CursorEndDrag`；
4. 在刷新前移除脚本上一次登记的回调，或使用“每个控件只绑定一次”的登记表，避免复用后重复触发；
5. 把回调闭包中的槽位换成最新运行时索引。

事件回调接收 `CursorEventData`。拖动期间可用 `data:GetUIPos()` 取得画布 UI 坐标；如果只需要按下位置或位移，使用 `GetPressUIPos()`、`GetUIPosDelta()`。

## 4. 拖拽幽灵的最小逻辑

`CursorBeginDrag` 时：

1. 用 `game.InstantiateClientUIControl(DRAG_GHOST_PREFAB_INDEX, root)` 创建独立控件；
2. 在幽灵中找直接子级“图片”（若幽灵根就是图片，则直接使用返回值）；
3. 从源项的“图片”读取 `imageSource` 与 `imageId`，调用 `ghostImage:SetImage(source, imageId)`；
4. 将幽灵置于合适层级，必要时 `SetAsLastSibling()`；
5. 关闭幽灵的“光标检测区域”射线；
6. 把幽灵位置设为 `data:GetUIPos()`。

`CursorDrag` 只更新幽灵位置。`CursorUp` 或 `CursorEndDrag` 时先销毁幽灵，再决定是否交换数据。不要移动网格自己管理的列表项，也不要把幽灵塞回网格。拖动取消、控件销毁和脚本停用都要走同一个 `DestroyGhost()`。

## 5. 换位、刷新与滚动位置

先交换本地 `slots[source]` 与 `slots[target]`，再刷新列表内容。刷新前读取 `grid.scrollProgress`，刷新完成后写回；写入前把值限制到 `[0, 1]`，需要诊断时再读回检查。换位刷新不能把滚动位置无故重置为顶部。

如果刷新回调异步完成，保存的进度应与本轮刷新代数绑定：旧回调不能覆盖新一轮的进度。刷新期间不要重复调用 `RefreshItems`；把“开始刷新、逐项绑定、完成恢复”写成一条状态流。

## 6. 容量、随机道具和服务器信号

随机道具测试按键（模板默认 Q）只改变本地数据并调用统一的 `RefreshInventory()`；它不是正式掉落系统。模板可在 `TEST_IMAGE_IDS` 中填写多个已确认图片资产 ID，让 Q 按顺序轮换；未配置时应打印缺少资产 ID，而不是伪造资源。扩容按键（默认 R）只增加容量上限，然后再次刷新，验证容量超过首屏（例如从 12 到 16）时仍会为新增索引绑定事件。容量应有明确上限，不能让按键无界增长。

交互后发信号时，用 API 声明的 `game.ServerSignal(name)`、`AddInt`/其他已确认的参数方法和 `SendSignal()`；信号名称、参数顺序以及服务器节点图里的字符串必须从工程契约填写。若没有服务器契约，模板只打印本地事件，不伪造“服务器已收到”。如需诊断，可选打印信号名、槽位、目标槽位和请求序号；回执由 `RegisterServerSignalHandler` 另行处理。

## 7. 自检清单

- [ ] `itemPrefabIndex` 来自已保存的列表项父模板；
- [ ] 网格项由 `RefreshItems` 管理，普通幽灵由 `InstantiateClientUIControl` 管理；
- [ ] 列表项内部有正式命名的“光标检测区域”；
- [ ] 每次回调都更新内容并绑定/去重 8 类事件；
- [ ] 拖拽幽灵不会拦截光标，且在所有结束路径销毁；
- [ ] 换位刷新前后保存并恢复 `scrollProgress`；
- [ ] 容量有上限，随机道具只是测试数据；
- [ ] 服务器信号的名称和参数来自节点图契约，并打印了对应字符串；
- [ ] 如需诊断，输出把 `documented`、`inferred` 和 `unknown` 分开；不把本地诊断输出写成通用运行结论；
- [ ] Lua 语法、API 标识、对象存活和清理路径已检查。
