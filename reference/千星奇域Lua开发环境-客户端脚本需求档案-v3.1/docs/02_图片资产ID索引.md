# 图片资产 ID 索引

## 1. 先分清图片资产和控件

图片控件的 `imageId` 是图片资源编号，必须和文档定义的 `imageSource` 一起使用。以下编号不能混用：

- 控件模板索引 `prefabIndex`：创建或查找图片控件模板；是否可动态创建还要看它是不是文档允许的模板父节点；
- 运行时控件 ID `id`：客户端实例身份；
- 图片资产 `imageId`：图片内容；
- 脚本映射 ID：脚本资源管理器中的映射身份。


看到“图片索引”“图片 ID”时，先问清它指的是哪一类。不要用控件的 `prefabIndex` 填到 `SetImage`，也不要把运行时 `id` 当图片资源。

## 2. 首选获取方式：编辑器记录

由创作者选择图片时，按编辑器当前版本操作：

1. 在客户端控件容器中选中目标图片控件。
2. 在属性面板找到图片来源和图片 ID，复制这两个值；如果图片来自模板，打开模板详情读取同一组值。
3. 记录控件名称、图片来源、图片 ID、用途和读取日期，交给脚本作者。
4. 代码中保留清晰的配置名，例如 `IMAGE_SOURCE` 和 `IMAGE_ID`，不要把数字散落在多个函数里。

如果属性面板没有显示 ID，不能凭图片名称、文件名或截图猜数字；把状态记为 `unknown`，请求创作者提供资源面板中的值。

## 3. 可选的本地资产索引

如果创作者另行提供资产清单，可以放在项目自己的 `assets/` 目录，例如：

```text
assets/image-index.json
assets/image-index.csv
```

清单至少应包含：

| 字段 | 说明 |
|---|---|
| `assetID` | 数字图片资产 ID |
| `source` | 图片来源类别或编辑器来源 |
| `name` | 人类可读别名 |
| `description` | 内容/形状/颜色等描述 |
| `evidence` | 清单来源、截图或文档路径 |
| `status` | `provided_unverified`、`observed` 等 |

AI 代选图片时，只做定向检索：先用主题、形状、颜色或用途筛选，再查看少量候选（例如 `rg -n -m 20 "关键词" assets/image-index.json`）。不要把大型 JSON 全部载入上下文，也不要因为描述相似就改写原始 ID。

若没有随包提供清单，不能假装包内存在资产 ID 索引；请创作者提供清单或直接从编辑器读取。

## 4. 绑定前的检查

绑定图片前建立一条记录：

```text
控件: CardArt
imageSource: <按 API 文档或编辑器填写>
imageId: <数字>
用途: 卡面主图
来源: assets/image-index.json#assetID=<数字> / 编辑器属性面板
证据: documented | provided_unverified | observed | unknown
真机状态: passed | failed | pending | not_required
```

代码中只能调用当前 API 文档声明的 `SetImage(imageSource, imageId)`，并确认目标对象存活。不要自行猜 `imageSource` 的枚举值；查阅规则见 [`01_API阅读与防混淆.md`](./01_API阅读与防混淆.md)。

```lua
-- 配置区：两个值都来自编辑器或本地资产清单
local CONFIG = {
    IMAGE_SOURCE = nil, -- 按 API 文档填写，未知时保持 nil，不要猜枚举
    IMAGE_ID = 0,       -- 本模板约定 0=尚未填写；真实资产是否允许 0 以编辑器为准
}

local function ApplyImage(imageControl)
    if imageControl == nil or not imageControl.alive then
        return false, "图片控件不存在或已销毁"
    end
    if CONFIG.IMAGE_SOURCE == nil or type(CONFIG.IMAGE_ID) ~= "number"
        or CONFIG.IMAGE_ID <= 0 or CONFIG.IMAGE_ID % 1 ~= 0 then
        return false, "图片来源或图片 ID 未配置"
    end
    -- SetImage 的签名和 imageSource 类型必须先回查 docs/客户端控件API文档.md
    imageControl:SetImage(CONFIG.IMAGE_SOURCE, CONFIG.IMAGE_ID)
    return true
end
```

这段代码只做配置和自检，不替代 API 查阅；真实枚举值由文档决定。

## 5. 交付时的资产索引表

每个实际使用的图片保留一行：

| 别名 | `imageSource` | `imageId` | 用途 | 来源 | 证据 | 真机状态 |
|---|---|---:|---|---|---|---|
| `CardArt` | `<文档值>` | `<数字>` | 卡面主图 | 编辑器/清单路径 | `provided_unverified` | `not_required` |

`documented` 只表示 API 声明了字段和调用方式，不表示这个工程里的数字一定存在。资产数字来自编辑器或清单时，按实际情况填写 `provided_unverified`；已直接观察到运行结果才写 `observed`。

## 6. 资产缺失或冲突

- 只有图片名称没有数字：暂停绑定，要求提供图片属性中的 ID。
- 同一别名对应多个数字：保留全部候选，注明来源和筛选理由，不擅自选一个。
- 清单与编辑器不一致：以当前编辑器为准，并把旧清单标为过期；不要覆盖原始清单。
- ID 为 `0`、空值或非整数：视为未配置，不发起 `SetImage`。

图片资产检索不需要创作者先进行真机验证。先完成名称、来源、ID 和证据记录，再由玩法需要决定是否观察显示结果。
