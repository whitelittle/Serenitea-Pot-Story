# 控件名称与 CONFIG 配置

来源编号：`REF-EDITOR-NAMES`。依据用户提供的简体中文编辑器“界面控件模板”面板，使用以下正式名称；名称查找匹配实际控件名称，不会自动把英文翻译成中文。

## 正式名称

| 面板名称 | 写作与查找规则 |
|---|---|
| 容器节点 | 用于分组或作为合适的脚本宿主；按实际名称查找 |
| 文本框 | 不写成假定默认名 Text |
| 文本视窗 | 与文本框区分 |
| 图片 | 单张预建图片示例默认名称为“图片” |
| 界面动效 | 与全屏界面动效区分 |
| 全屏界面动效 | 不自行缩写默认名称 |
| 预设按钮 | 不写成假定默认名 Button |
| 按键提示 | 与预设按钮区分 |
| 光标检测区域 | 单个区域示例使用此正式名称，不假定为 CursorArea |
| 网格视窗 | 不猜英文默认名 |
| 模板引用控件 | 与被引用模板中的子控件区分 |

## 按钮术语与防混淆清单

本包按**结构**区分按钮，统一使用以下名称。“组合式按钮”是本文对实现方案的称呼，不是编辑器中可选择的新控件类型。旧材料或未改动模板说明中的“动态按钮”若指下述组合结构，按“组合式按钮”理解；新说明不用“动态按钮 / 静态预设按钮”作为类型对照。

| 对照项 | 组合式按钮（自定义交互） | 预设按钮控件（编辑器四态） |
|---|---|---|
| 结构与类型 | 容器节点、显示控件、光标检测区域的组合 | `ClientUIPresetButtonControl` 及其配置的状态子层级 |
| 外观来源 | 组合中的图片、文本框等显示控件 | 当前状态的显示子控件；模板引用方案由引用的模板内容提供 |
| 光标事件接收者 | `ClientUICursorEventAreaControl` | `ClientUIPresetButtonControl` 本身 |
| 状态管理 | Lua 显式管理悬停、按下、禁用等自定义表现 | 编辑器配置四态槽位与样式，脚本使用文档声明的交互接口 |
| 运行时更新 | 按显示控件类型更新内容、布局或 Tween | 同样可按对应类型更新已取得的显示子控件，也有继承的布局/变换能力；状态绑定仍按编辑器配置 |

**创建时机和结构是两回事。** 两种结构都不应仅凭名称被判为“只能预建”或“只能运行时创建”。能否动态实例化，取决于目标是否已保存为可实例化的模板父节点、模板索引和父级是否有效（查 API §6(1) 与官方指南）；动态实例化预设按钮模板不等于 Lua 能凭空补齐四态配置。“静态”只在明确指当前内容不变化时使用，不作为预设按钮的类别名。

写代码或交付前检查四项：

- [ ] **结构明确：** 已说明采用组合式按钮还是预设按钮控件；不因为需求含“动态”“动画”就自动更换现有结构。
- [ ] **外观有来源：** 已指出实际显示控件及内容；预设按钮还需核对当前状态绑定和模板内容，不承诺空按钮自带外框。
- [ ] **事件与字段归属正确：** 光标监听注册在正确类型上；文字和颜色写到显示控件，不能套到按钮本体或容器上。
- [ ] **行为与证据分开：** 分别说明是否动态创建、更新哪些内容；点击有响应不证明外观显示，模拟点击也不证明真实命中。

## 组合式按钮推荐结构

<a id="动态按钮推荐结构"></a>

需要自定义交互和状态表现的新按钮，优先采用以下组合。已有预设按钮仅需更新图片、文字或动画时，先检查现有显示子控件的 API，不因“需要动态变化”就强制改结构：

```text
容器节点（按钮根）
├─ 图片 / 文本框 / 其他显示内容
└─ 光标检测区域
```

脚本挂在这个 `容器节点` 或其明确的脚本宿主上。父级容器开启 `showCursor`，`光标检测区域`开启 `raycastTarget`，Lua 在光标事件回调中修改图片、文字、颜色、显隐或 Tween。光标检测区域负责命中和事件，不负责显示按钮外观；显示内容仍由“图片”“文本框”或子容器组成。需要多个显示控件时，继续把它们放在容器节点下，不要把它们改成预设按钮的四个状态槽位。

适用场景包括动态换图、文字变化、悬停放大、按下变色、淡入淡出、拖拽反馈和自定义禁用逻辑；这些效果不专属于某一种按钮结构。需要编辑器管理四态、按键样式和点击音效时，阅读 [预设按钮四态与样式](10_预设按钮四态与样式.md)。组合式按钮的 API 关键字为 `ClientUIContainerControl`、`ClientUICursorEventAreaControl`、`ClientUIImageControl`、`ClientUITextBoxControl` 和 `AddCursorEventListener`。

## 预设按钮的特殊子树

在本项目已确认的预设按钮做法中，每个状态槽位只绑定一个根控件。使用四态模板引用时，预设按钮下准备四个直接子级 `模板引用控件`，分别把它们放到：

- `默认状态节点`
- `悬停状态节点`
- `按下状态节点`
- `不可用状态节点`

然后在界面中选择或配置对应的按键样式。每个 `模板引用控件` 只设置一个模板控件索引；被引用模板在模板库中独立保存，不作为该引用控件在按钮层级中的子控件显示。需要多个 `图片`、`文本框` 或其他内容控件时，把它们放进另存的模板根 `容器节点` 内，再将该模板索引填入一个引用控件。四个引用如果自动生成了相同名称，应先在编辑器中改成不同的实际名称，再写入 CONFIG。完整准备步骤见 [预设按钮四态与样式](10_预设按钮四态与样式.md)。

Lua 只读取 `ClientUIReferenceControl.referencedPrefabIndex` 做诊断，不能给它赋值，也不能用四个运行时控件 `id` 替代模板引用。按钮点击监听仍注册在 `ClientUIPresetButtonControl` 本身。

这是界面名称表，不是 Lua 类型/方法表。`ClientUIImageControl`、`imageColor`、`GetChild`、`FindChild` 等 API 标识仍按 API 文档写英文；局部变量 `image`、逻辑状态 `idle` 也不等于控件名称。

## 名称放进 CONFIG

```lua
local CONFIG = {
    IMAGE_NAME = "图片",
    CURSOR_AREA_NAME = "光标检测区域",
}
local image = script.object:GetChild(CONFIG.IMAGE_NAME)
local area = script.object:GetChild(CONFIG.CURSOR_AREA_NAME)
```

`GetChild` 只查直接子控件；`FindChild` 的路径须对应实际层级。控件重命名为“卡面”时，把 `CONFIG.IMAGE_NAME` 改为 `"卡面"`。若移到另一层级，还应调整相对路径和查找方式，不能只改显示文字。

多个同类型控件不能靠正式类型名区分用途，也不假定编辑器自动追加什么后缀。先给它们不同的实际名称，再填写配置。未填写时教学模板给出提示并停止该功能，不猜名字；完成文档和玩法编写不受此阻塞。

## 本包具体改哪里

| 示例 | 名称/路径配置 | 准备方式 |
|---|---|---|
| 手写教程的单图片例 | `CONFIG.NAME` | 默认“图片”；改名后填实际名字 |
| 09 逐帧 | `CONFIG.FRAME_GROUP_PATH`、`CONFIG.STATES.<状态>.path`、`.frames` | 帧总组可用“容器节点”；每个状态组需区分名称，frames 按顺序填实际帧控件名/相对路径 |
| 11 遮罩与抖动 | `CONFIG.TOP_MASK_NAME`、`BOTTOM_MASK_NAME`、`WORLD_SHAKE_NAME` | 创建两张“图片”和一个“容器节点”；给它们不同名字并填写对应角色 |
| 12 状态切换 | `CONFIG.IDLE_NAME`、`ACTION_NAME` | 创建两个“容器节点”或适合的状态根，区分命名后填写 |
| 13 输入适配 | `CONFIG.IMAGE_NAME`、`CURSOR_AREA_NAME` | 默认“图片”“光标检测区域”；实际重命名后同步填写 |

“上遮罩/下遮罩/画面抖动”“待机/动作”等可作为自己起名时的例子，**不是编辑器默认名称**。不要求采用这些建议名字，现有工程有命名就沿用现有工程。

## 用户和 Agent 如何配合

- 用户手改：在编辑器重命名，再修改上表对应的 CONFIG 项；路径中的父级与子级也要同步。
- 用户让 Agent 改：说明当前名字、想改的名字或目标用途。Agent 负责修改 CONFIG、所有相关引用和准备步骤，并检查查找的父级范围。
- 已有层级或配置足够时直接使用，不重复追问；同名冲突或层级缺失会影响下一步时，只询问对应信息。
- 变量名、API 名和控件名分别处理，不全局替换 API 标识，也不把重命名变成强制真机任务。
