# 多文件进阶示例

这套示例用一个入口和三个小模块展示职责拆分，适合已经能手写单文件脚本、需要继续整理代码的人。第一次写 Lua 请先读 [`docs/06_新手手写Lua模板.md`](../../docs/06_新手手写Lua模板.md)。多文件拆分只是一种可选组织方式；它不依赖上一层工程，也不要求使用 OOO 或其他外部项目。

## 文件树

```text
external_lua_file/
  入口文件示例.lua       -- 唯一生命周期入口
  core/runtime.lua       -- 状态、清理、错误边界
  data/balance.lua       -- 只放数值
  ui/hud.lua             -- 一个简单的文本控件示例
```

例子刻意没有放输入、坐标换算、网络信号、对象池或通用 UI 框架。需要这些能力时，为具体玩法增加模块并写清它的清理契约，不要复制暂时不用的基础设施。

## 什么时候建立脚本映射

可以先在本地写完并静态检查文件，**不要求在编辑器里预先登记后才能编码**。准备运行时再做三件事：

1. 在客户端脚本资源管理器中为入口和每个被加载的 `.lua` 文件建立脚本映射；
2. 在客户端控件的脚本页签挂载入口文件；
3. 保存；需要观察运行行为时再试玩，不作为完成编码的前置任务。

官方使用指南 [`docs/千星沙箱客户端脚本使用指南.md`](../../docs/千星沙箱客户端脚本使用指南.md) §七只确认了映射与本地文件关联后才会上传运行，以及脚本如何挂到控件；没有规定 Lua `require` 的路径格式。§八提到可以通过 `scriptMappingId` 调用其他脚本，这是跨脚本 API 方向，也不能证明 `require` 的路径语法。本例的目录和模块组合是教学结构，不因此自动得到客户端运行保证。优先沿用当前工程已知可用的加载方式；没有依据时可先交付单文件实现，保留拆分结构。最小模块运行观察仅为可选补充，不强制创作者执行。

## 依赖关系

```text
入口文件示例.lua
  ├─ require → core/runtime.lua
  ├─ require → data/balance.lua
  └─ require → ui/hud.lua
```

模块不注册 `OnInit`、`OnUpdate` 等全局回调；只有入口注册。模块间不互相 `require`，共享状态通过 `Init` 参数传入。模块出错返回 `false, message`，由入口统一进入故障状态，不在模块里静默吞掉错误。

## 使用顺序

1. 复制文件并先读入口中的配置和注释。
2. 给 `require` 装载点注明已有工程依据或尚缺的条件，先完成静态检查。
3. 在编辑器建立映射并挂载入口后，逐项填写模板索引；未填写的值会安全拒绝对应功能。
4. 交付时说明每个文件是否已映射、API 是否静态回查、是否做过运行观察。证据规则见 [`docs/07_自我约束与证据回报.md`](../../docs/07_自我约束与证据回报.md)。

## 这套示例故意不做的事

- 不把 `prefabId` 当成字段。客户端控件模板索引使用 API 文档声明的 `prefabIndex`。
- 不把 `pcall` 当成“出错就算了”。`pcall` 只包住宿主边界并把错误返回给入口；模块必须让入口知道失败。
- 不强制填写容器节点或控件索引。入口通过 `script.object` 获取挂载宿主；模板索引为 `0` 时，示例记录原因并跳过 HUD 功能，不调用空索引。
- 不声称 `require` 已在所有编辑器版本实测通过；官方指南没有写出它的路径规则。
